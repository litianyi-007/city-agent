# 第一批模拟软件需求

用户于 2026-10-07 明确要求自拟三个模拟需求，没有真实业务工单或需求提出者。以下案例是展示输入、规格、实现、验收、反馈与交付的模拟演练，不满足申报规则中的“至少三项真实需求”。输入注册表为 [production-benchmarks.ts](https://github.com/litianyi-007/city-agent/blob/5b91af1ecf7e20fff56789ab0b2d0e2c951d9bda/shared/production-benchmarks.ts)，不根据用户关键词硬编码真实任务的产物。

## 模拟案例

| 编号 | 类型和背景 | 输入 | 主要验收 | 难度 |
| --- | --- | --- | --- | --- |
| MOCK-01 | 新建三人小组待办板 | 一句话目标、离线约束 | 添加、完成、删除；输入清空；实际条目和统计精确对应 | 低 |
| MOCK-02 | 受控待办模板增加筛选 | 原交互约束、筛选需求 | 全部/未完成/已完成；不丢原任务；总数与完成数保持 | 中 |
| MOCK-03 | 修复模拟空任务缺陷 | 空白重现、连续输入及删除反例 | 空白拒绝；两次添加恰好两项；删除一项保留另一项 | 中 |

Mock 的角色响应与产物由工程夹具提供，真实 Chromium 验收会执行，但不是 LLM 自主编写软件。增加功能和 Bug 修复在本批演练中是受控 HTML 的行为与契约验证，不宣称已经修改任意既有仓库或完成真实模型的缺陷定位。

同一需求可以切换为 live 模式，让配置的内部 Agent 生成候选；不得将 mock 专属 fixture 注入 live。该运行即使通过，也仍属于“模拟需求上的真实模型交付”。

## 权限与预算

本批仅离线单 HTML；无外网、后端、主机脚本、依赖安装或发布。产品和项目经理遇到无法支持的目标应拒绝，不偷偷缩减目标。每角色可用相同或不同 Provider/Model ID，不把 ID 不同视为模型权重独立证明。

用户负责页面配置新 Key 和模型单价。成本采用首批 15 USD、单次 5 USD 的保守限制，同时限制时间、Token、调用和返修。若价格/usage 缺失，费用为 unknown，停止后续付费调用。初始目标与授权不算运行中的人工返修；取消与人工修改须另行记录。

## 人工基线预测

MOCK-01 为 0.5–1 人日，MOCK-02 为 0.3–0.75 人日，MOCK-03 为 0.25–0.5 人日。假设熟悉 HTML 的研发负责实现、自测和交付，1 人日为 8 小时。这些是计划估算，不是历史工时，不用于计算已实测增效。后续同目标、同验收、同范围的人工对照才可提供有效比较。
