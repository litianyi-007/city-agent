# 自动化软件生产验收草案

此处作为第一批的冻结验收框架，不是已通过清单。用户已明确六角色、三个模拟需求与高性价比预算；无官方 L4 原文，按操作性定义自评。正式实验前冻结配置版本、输入及检查 hash；修改 Gate 或 Prompt 后开启新实验版本。准备阶段原文在 archive/EVALUATION.md 留底。

L4 指明确目标、权限和预算后自主执行，只有必要信息或越界决策才请求用户。这里的有界 L5 指明确授权范围内，需求到验证交付没有中途人工改产物或放宽 Gate；不代表任意环境的通用 L5。

## 硬门限

| ID | 最低要求 | 失败或证据口径 |
| --- | --- | --- |
| PE-01 | 用户目标、仓库范围、业务验收、权限、模型与预算明确 | 缺失关键项不能猜测或自动扩大范围 |
| PE-02 | 六角色独立配置、复制、脱敏、禁用生效；路径、数据和端口隔离 | 更换端点不隐式转移旧 Key；原线服务不受影响 |
| PE-03 | 产品规格和测试契约在研发前冻结；预检选择器语法、作用域及业务覆盖 | 非法测试拒绝并反馈；返修不得修改 hash 或删失败项 |
| PE-04 | 实际构建或浏览器验证功能；数值精确核对，反例能失败 | 不接受模型自述通过、可见按钮或仅文本变化作为充分业务验收 |
| PE-05 | 两次自动返修上限；明确整次时间、调用、Token 与金额限额 | 到上限停止并保存部分结果；无价格依据须 unknown，不猜测金额 |
| PE-06 | 每次请求、失败、原文、usage、Prompt/config、代码及验收版本可追溯 | 缺失分项注明 unknown；不覆盖旧尝试，不以最终回复代替全部账本 |
| PE-07 | 取消停止调用、执行和相关子进程；重启保留真实状态 | 不自动重复付费请求；清理与预算中止须有负向测试 |
| PE-08 | 执行生成 Node/shell 前通过隔离、路径、秘密、网络、资源和取消测试 | Worktree 不替代沙箱；不可用时拒绝该执行范围，不降级宿主执行 |
| PE-09 | 既有虚拟社会接口、调查、人口和配置回归通过 | 验证只在新 worktree 内，未跑项不引用旧结果冒充本轮通过 |
| PE-10 | 交付包有 base commit、源码/patch、依赖、lockfile、复现步骤、测试、预览和 manifest | 产物来源明确；不能用模板回退、人工改代码或旧交付冒充自主成功 |

PE-08 对新增 Node/shell 范围是不可跳过的前置条件。纯受限 HTML 仍须验证浏览器隔离和外部请求限制，不自动宣称面对恶意代码完全安全。

2026-10-07 评审修订采用 `production-html-v2` / `production-acceptance-v2`：`assertValue` 和 fill 驱动的 `assertChanged` 只能辅助，不单独构成业务结果资格，避免不同 CSS 别名指向同一原生输入的镜像验收。这个机械门限仍不能证明所有用户业务要求都覆盖。旧 v1 运行及 hash 保留，不把新契约重标到旧实验。

新增安全硬反例：生成页面延迟自导航不得向实际本地外部服务器发出请求；源 HTML 必须文本附件；前端没有生成产物 iframe；受控截图取消/超时清理及单并发有效。公开入口仅接受逐字验证的可信 Mock，任意模型产物不能复用其交互授权。旧 iframe 录屏不是修复后的安全证据。凭据需满足新输入策略，字面、JSON 转义和对象属性名等已测变体均不得出现在原文日志、Prompt 或导出；未知变体不作绝对保证。

## 第一批真实闭环

六角色都实际参与一次任务，遵守适用硬门限，最终 Gate 通过，期间无外层人工改生成产物、无临时放宽断言、无模板回退，才称“最小真实闭环通过”。单次通过不称稳定通用 L5。Mock 三案例只计工程演练；真实模型完成模拟需求与真实业务需求交付分别统计。

当前基线六次尝试未取得该结果。准备阶段 109 项测试、5 项浏览器回归和构建只证明已有工程基线可复现，不满足本节真实闭环门限。

正式任务开始前记录模型 selector、Provider/端点、可观察的响应证据与身份核验限制。远程端点、不同 ID 或 SDK 使用不能独立证明实际底层权重身份。干预记录必须说明实际发生的动作，不能仅写入固定 humanIntervention=false。

## 稳定性实验草案

采用用户提出的初始门限：两个公开开发任务和一个未见任务，每类三次，总计九次；总体至少八次成功且每类至少两次成功，安全、秘密隔离和 Gate 不可修改等硬门限全部通过。该样本量仅服务有界 Demo 验收，不证明普遍可靠性。

真实实验前明确任务、成功定义、预算、超时、允许返修、依赖、Prompt、模型和验收版本。未见任务不用于 Prompt 或实现调优；若用于修订，失去该轮未见身份，须另设留出。

每次从干净任务目录启动。配置改变则另起版本，不混并成功率。所有启动尝试进入账本，失败、取消、超时、截断和未完成单列；不能仅保留成功者，也不能靠新增题目专用分支补救后声称泛化。

重复轮次必须使用新 run/session/request 身份、独立模型调用，绕过应用层已有答案和选择缓存。允许复用冻结输入，不允许复用已作答结果；供应商前缀/KV缓存另列，不冒充答案缓存关闭的证据。每轮调用意图先独立落盘，初始 running manifest 不与最终报告共享可回滚事务；中断、最终报告提交失败均保留启动记录，恢复不自动重放收费请求。VE-02/03 [注入合同](https://github.com/litianyi-007/city-agent/blob/5b91af1ecf7e20fff56789ab0b2d0e2c951d9bda/docs/production/VERIFIER-STUDY-CONTRACT.md)只证明此执行器工程边界，不替代真实稳定性实验。本次[原文留底](https://github.com/litianyi-007/city-agent/blob/5b91af1ecf7e20fff56789ab0b2d0e2c951d9bda/docs/production/archive/2026-10-07-before-verifier-study/EVALUATION.md)。

## 业务数据

分别报告模型耗时、工具/构建/测试耗时、整次墙钟时间、调用数、格式重试、返修、输入/输出及缓存 Token。分模型、分币种记录单价和适用时点，区分估算与实际账单。缺失 usage 或费用为 unknown，未启动请求与失败请求的计量不能混淆。

外层 Codex 建平台、内部 Agent 真实交付及 mock/夹具分开计数；Hopper 评审也单独登记。良品率分母保留该配置所有启动尝试，取消、超时、失败、未知不静默排除；首轮与最终通过分别报告。自主环节按固定产品/研究/项目计划/测试契约/研发/项目反馈六环节证据统计，不以拆分次数增加占比。系统外的人工行为不可仅靠空数组证明。

## Verifier 门限

每个可替换角色输出先过结构契约，再以冻结 rubric 交给独立 Verifier。单候选仍检查；多候选只有达到最低序数门限且评分最高者可选择；所有候选不合格、评分缺失、ID 错误、非法 JSON 或弃权均不得默认放行。不缓存跨需求评分，不把序数当概率。实际功能与安全 Gate 失败时，Verifier 高分不能交付。

补充负例包括：数字 10 不能通过精确值 1 的断言，任务统计不能代替实际元素数；非法 CSS 在研发前拒绝；空白任务不加入；全部候选低分不选；取消记录不被覆盖；最后一次响应超预算也必须失败。首批内部限额为每次 5 USD、合计 15 USD，不承诺费用节省或供应商发票硬上限。

## Jev 对照预登记 v1

固定 `jev-1.13.0` 和 `jev-candidate-v1`；每候选覆盖性/一致性/范围 Score 期望≥3/4、分布集中度≥0.5，范围 Noul 和 Choice 也满足集中度门限。算法检查分布归一、期望及集中度一致性。集中度不等于业务准确率。只按固定门限记录，不在看结果后降低阈值。

对照池 `jev-engineered-candidate-pool-v1` 含三项 MOCK，每题两份人工构造源码：一份参考夹具、一份业务缺陷。候选中立 ID，第一题/第三题缺陷在前、第二题参考在前；不是随机代表性样本。源码、业务测试、配置与池 hash 外呼前落盘，不向 Jev 暴露缺陷标签或 Gate 结果。先决策，再对全部候选跑实际 Gate，报告首候选通过率、选中通过率（分母含弃权）、选择覆盖率及仅已选择的通过率，保存所有失败。

最多3个单次不重试请求；总 Token 196608、估算费用1 USD，缺 usage 停止后续。API 错误不能自动换模型。混合 Mock-Jev 使用固定代码与真实决策，不计内部 Agent 自主交付；live 不确定时才升级一次 LLM Verifier。泛化、概率校准和人工效率改善仍须独立标注集与真实实验。
