# 项目基础介绍

## 一、项目概述

City Agent Autonomous Production 源于小型软件需求中普遍存在的协作痛点：需求常以一句话提出，但从需求澄清、方案研究、任务拆解到开发、测试和交付，需要反复协调多个角色；常规 AI 编码工具虽然能够生成代码，质量判断、返修和交付整理仍依赖人工串联。

项目以“拟人化研发团队”为产品形态，设置产品经理、项目经理、研究员、研发、测试与 Verifier 六类 Agent，将分散的 AI 能力组织成可观察、可验证、可追溯的软件生产流程。用户可以为角色独立配置模型，提交需求、验收与预算，跟踪任务分工、候选评价、测试反馈和交付记录。项目面向 L4/L5 有界自主研发，当前聚焦小型页面与受控交互场景，逐步把“一句话需求”转化为明确产品目标和可验证的实现任务。

## 二、项目创新性

核心创新是将“生成能力”与“质量决策”分离，构建“六角色协作＋项目经理 Agent Loop＋分层 Verifier”的研发管线。

系统将产品目标扩展、约束研究、任务规划、实现、测试契约生成与候选复核分配给 AI 角色。项目经理提供规划与反馈，确定性编排器负责阶段推进、预算与终止，共同组织“思考→设计→实施→测试→反馈→再规划”的有界闭环；独立 LLM Verifier 按细粒度标准评价本次候选，托管 TypeSafe Jev 提供结构化快速决策，不确定时再升级独立 LLM 复核。最后以冻结的实际功能 Gate 作为交付依据，使模型评价与可执行验证相互补充。

角色、模型、输出契约、验收与证据记录分别管理，支持模型组合、Agent 复制和多类需求复用。每次执行保存输入、原始输出、版本、测试、Token 和估算费用，便于复现与持续改进。后续计划参考 AnyJev 扩展类型化决策适配器，使质量决策层可替换、可评估。

## 三、价值贡献

项目已形成可运行的六角色研发工作区、分层候选验证、验收冻结、有限返修及执行证据管理原型，并通过新建应用、功能扩展、Bug 修复三类工程案例展示流程和页面行为验证；真实模型试验为契约和决策层优化提供了可追溯数据。

其价值在于把原本依赖个人经验和反复对话的软件研发流程，转化为统一的角色职责、验收规则与可核查记录，提升需求明确性、质量透明度和成本可观察性。应用潜力包括团队内部小工具、交互原型、标准化页面和受控功能迭代，适合小团队与非专业需求提出者使用。

推广采用“先受控场景、再受控仓库”的路径。预期收益是减少重复协调、提高验收一致性、缩短问题定位时间；效率提升与商业收益将通过同范围任务对照评估，当前以工程验证和实际调用记录为依据。

## 2. 管线设计、人工边界与复用

~~~text
用户：目标 / 范围 / 模型 / 预算授权
  → 产品经理扩展目标 → 研究员核对约束 → 项目经理设计任务
  → 测试生成验收 → 结构与选择器预检 → 冻结版本与 hash
  → 研发实现 → 候选验证 → 确定性浏览器功能 Gate
  → 达标：源码 / 截图 / 证据包
  → 反馈：项目经理重规划 → 剩余额度内返修
  → 取消、超时、超预算或协议错误：停止并保存记录

各阶段候选：
  实际 schema 预检 → Jev 快速决策或独立 LLM Verifier
                         ↓ 不确定 / 已分类的派生算术异常
                    原预算内一次独立 LLM 复核

控制面：角色、模型、加密 Key、预算
执行面：受限产物与浏览器功能测试
证据面：输入、候选、调用、契约、Gate、返修和费用
~~~

| 环节 | AI 职责 | 门禁标准 |
| --- | --- | --- |
| 产品经理 | 扩展原话为目标、用户故事、范围和验收。 | 实际输出契约有效，业务必需项与原目标一致。 |
| 研究员 | 研究实现选择、约束和风险。 | 区分事实、推断与待确认项，遵守授权范围。 |
| 项目经理 | 提出任务计划、阶段判断与修复建议；确定性编排器执行阶段推进和返修。 | 版本化决策；编排器维护冻结验收，生成前纠错与研发返修共享最多两次全局额度。 |
| 测试 | 生成可执行验收、分析实际结果。 | 研发前预检并冻结测试版本与 hash，保留功能和负向用例。 |
| 研发 | 根据规格、约束和冻结契约实现及返修。 | 产物来源可追溯；返修保持冻结 Gate 不变。 |
| Verifier / Jev | 按细粒度 rubric 评价本次候选、选择或弃权。 | 输出结构、候选引用、质量与范围阈值有效；独立于生成职责。 |
| 确定性 Gate | 实际页面操作与精确结果检查；摄像头场景另有必需行为校验。 | 以可观察功能行为作为依据，模型评分作为辅助。 |
| 交付与记录 | 汇总输入、模型、Prompt、源码、调用与测试记录。 | 所有启动尝试及状态可查，缺失计量明确标记。 |

默认单候选以控制成本，可按预算配置多候选，Verifier 在本次合格候选池内选优。模型 Key 在控制面加密保存，页面支持独立模型配置、Agent 复制与 Key 轮换。

人工负责初始目标、权限、模型、预算与最终采用；必要信息和越界选择由用户决定。平台建设与单次内部任务分别计量；运行中的人工调整必须登记。项目经理闭环以有限返修和明确终止管理执行资源。

复用通过角色输出契约、模型配置、验收、预算/取消和证据协议实现。任意仓库扩展列入受控执行器路线：先验证容器、路径、网络、资源和秘密隔离，再开放相应能力。当前受限 Chromium 防护与开发 worktree 分别承担执行控制和研发隔离，安全边界见 [设计](DESIGN.md)。

## 6. 核心创新与持续改进

### 分层 Verifier：质量与成本共同治理

参考 [LLM-as-a-Verifier](https://github.com/llm-as-a-verifier/llm-as-a-verifier) 的细粒度评价与反馈思路，项目实现结构化序数 rubric、候选引用校验、选优/弃权和反馈记录。实现采用可审查契约，不依赖生成者自评；多候选按预算开启。

托管 [TypeSafe Jev](https://docs.typesafe.ai/introduction/coding-agents) 已接入决策设置、加密 Key、Score/Noul/Choice 评审与独立计量。它负责快速结构化决策，角色 LLM 负责目标与产物生成。live 不确定时升级一次独立 LLM Verifier；`jev-candidate-v3` 对完整协议预检后已分类的派生算术异常也采用一次独立复核，保留原始响应与来源链路。

合成候选池 v2 三题中，首候选 Gate 1/3，含弃权的选中率2/3，选择覆盖率2/3，已选择条件通过2/2。这组固定合成池用于观察质量决策的接受与弃权行为，支持后续设计更具代表性的评估。CAMERA-04观察到三次正常不确定升级；v3算术分支已有免费工程夹具覆盖。

### 可追溯 Agent Loop 与实施路线

项目经理产出任务规划与反馈，由确定性编排器维护冻结验收、预算额度与终态。下一步沿同一管线推进：

1. 引导 Verifier输出紧凑结论，维持既有结构上限；CAMERA-04的1428字符原因字段为具体优化依据。
2. 增加测试语义预检，识别未展开 `{{particleCount}}` 与粒子总数不变量冲突，将反馈交给原测试角色有限纠错。
3. 明确场景 schema、必需几何行为、CSS验收、真实视觉与实体设备的覆盖职责。
4. 免费反例验证后冻结新配置、开展独立预登记任务，再进入固定配置的稳定性评估。
5. 参考 [AnyJev](https://github.com/nokia-applied-research/AnyJev) 扩展类型化 retry/replan/terminate 适配器；后续评估本地 SDK、模型读出能力与独立标注校准。
6. 验证受控执行环境后扩展小型仓库，并以两个公开任务、一项未见任务各三次的固定实验评估泛化。

托管 Jev 为当前已实施能力，AnyJev本地 SDK 为下一阶段方向。质量决策层与任务状态机分别演进，方便替换模型、复用角色和比较不同成本/质量策略。

## 7. L4 自评与复用推广

本项目采用“用户明确目标、权限、范围和预算后，团队自主推进并保留可验证交付证据”的有界自主研发定义。当前阶段为六角色工作区、质量决策与受控执行的研发原型，自评重点为角色配置、执行可观察、验收冻结、预算/取消和证据完整性。

推广优先面向内部小工具、交互原型和标准化页面；通过固定输入、验收、模型与成本配置复用管线，再逐步扩展受控仓库。稳定性阶段建议总计九次、至少八次成功且每类至少两次成功，同时全部安全硬门限通过；门槛在试验前预登记，作为有界 Demo 的工程评估标准。
