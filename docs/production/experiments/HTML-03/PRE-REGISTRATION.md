## 原始需求与输入

需求原话：

> 为小团队做一个无需登录、无需网络的单页费用记录页：填写描述、金额并选择“办公/差旅”后添加记录，支持删除及“全部/办公/差旅”筛选，准确显示全部费用总额和当前筛选小计；金额只接受0.01至9999.99元（含边界）、最多两位小数，无效金额或空白描述应提示且不得入账，数据仅在当前页面保存。

## 业务验收

以下是需求的预期行为与测试数据，不是预填测试角色输出。测试角色应自主选择合法普通 CSS、节点层级与检查组织，在研发前经结构/语义预检和独立评审后冻结完整 checks 与 hash。

1. 初始实际记录数0，全部总额与当前筛选小计均精确为 `0.00`。某分类没有记录时，实际显示0条、小计 `0.00`，不产生占位记录冒充费用。
2. 添加“打印纸／办公／10.10”和“车票／差旅／20.20”后，实际只有2条，描述、分类和金额准确；全部总额及全部筛选小计为 `30.30`。每次成功添加后描述、金额输入清空。
3. 办公筛选只显示“打印纸”1条、小计 `10.10`；差旅筛选只显示“车票”1条、小计 `20.20`；全部总额始终为 `30.30`。切回全部恢复原2条，不复制、丢失或修改记录。
4. 在独立新页添加 `0.10` 与 `0.20` 两笔后，实际2条，总额与全部小计精确为 `0.30`，不是浮点尾数或输入拼接；删除其中 `0.10` 一笔后，另一笔保留且总额为 `0.20`。
5. 单条下界 `0.01` 和上界 `9999.99` 均可入账且分别只新增1条；两笔合计精确为 `10000.00`。上限属于单条金额，不能错误限制全部费用总额。金额显示保留两位小数。
6. `-1`、`0`、空金额、`1.234` 和 `10000.00` 均提示并拒绝。分别在空列表及已有有效记录的状态下核对：拒绝后实际记录数、已有内容、全部总额与当前小计不变。不得将空值当0、负数取绝对值或超精度金额静默四舍五入后入账。
7. 空白描述（包括纯空格）即使金额有效也提示并拒绝，实际记录、内容与总额保持不变。
8. 分类筛选状态下删除只移除目标记录并立即更新小计、全部总额；切回全部后其它记录仍在。删除最后一条后实际记录数0、总额与小计均回到 `0.00`。

各独立 check 自行 setup，不依赖前一个检查的页面状态。建议把业务序列拆成约9–11项检查，但不得用建议数量替代自主设计；宿主最多12项、每项最多20步。分类选择和筛选要能通过 click 操作，业务由明确按钮 click 驱动，不能依赖原生 form.submit。使用独立业务内容/金额节点做精确断言，使用实际条目容器做数量断言，不能以按钮可见、输入回显或整行含操作按钮的文本替代业务验证。

当前 Gate 只有 fill/click 等已登记动作，没有 reload、键盘或 selectOption；不把未发生的刷新/持久化验证写成通过。页面仅当前页内存保存是范围约束，不扩展为本轮必须新增平台动作。

正常6个被评审阶段为产品、研究、首次项目规划、测试、实现、Gate后项目反馈；每阶段1候选加1次独立 Verifier，故正常 **12个逻辑 Harness 调用意图**。两次修复均为 Gate 返修时最多20；两次都用于研发前重新走产品/研究/规划时，最坏最多 **24个逻辑槽位**。合法池为空可能不外呼 Verifier，致命拒绝也可能提前终止；24不是必须消费或保证能执行完的数量。项目经理在正常流程出现两次，不漏计第二次反馈评审。
