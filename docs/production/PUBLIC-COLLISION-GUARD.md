# 启动公共协议碰撞守卫 v2

## 问题与范围

[HTML06](experiments/HTML-06/RESULT.md)实际启动在首模型请求前因守卫工作量超限失败。旧算法对每个当前/历史加密凭据代际，重复枚举公共 UTF-8 字节窗口并完整 AES-GCM 加密；在有界合成历史配置中可复现超限。没有检查实际私有 Key/主密钥/状态，因此不把合成规模当作实际配置的测量。

`public-collision-guard-v2` 优化实现，不关闭碰撞检查、不删历史、不缩短固定指令，也不改变业务验收、Verifier标准或原12×20 Gate。算法只用于判断公开材料是否与遗留凭据碰撞，不作为授权或凭据有效性验证。

## 加密比较与资源边界

1. 校验公共结构、字节、深度与节点；不执行 getters、Proxy traps 或 `toJSON`。保留解码后的字符串、属性名及原序列化 token 的扫描范围；可选字段 `undefined` 按原 JSON 语义省略/数组 null，顶层无法序列化仍拒绝。
2. 覆盖全部当前与历史 Agent/Jev 密文代际。相同完整密文去重，按密文字节长度分组；公共窗口按不同长度仅枚举一次。
3. 针对每个 IV 加密公共的16字节零块，得到本次局部加密掩码。仅计算 **公共候选前缀 XOR 掩码** 与密文前缀比较；绝不计算“已存密文 XOR 掩码”来恢复私有明文。
4. 前缀相同仍不证明碰撞；必须重新完整 AES-GCM 加密公共候选，完整密文和认证 Tag 均相等才拒绝。不同后缀、不同 IV 和错误 Tag 均有反例验证。无解密、秘密摘要、代际/长度/扫描计数导出或跨调用缓存。

| 硬限制 | v2 口径 |
| --- | --- |
| 公开 JSON | 最多1 MiB、100000节点、深度40；解码材料亦有字节上限 |
| 凭据格式 | 规范base64；IV12 / Tag16 / 密文16–500字节；遗留坏格式拒绝 |
| 扫描 | 全局最多100000实际字节窗口位置，窗口去重前计数，按不同长度枚举；旧版是逐代际重复计数 |
| 加密 | 全局最多100000实际加密操作，零块与完整认证比较都计入 |
| 前缀比较 | 新增独立全局1000000次上限，每次比较16个公共候选加密字节；不是把旧加密上限改成1000000 |

这是公开定义的算法与工作计数版本变更，而非宣称所有资源消耗与旧版相同。任何上限触发仍失败关闭；更大配置仍可能被拒绝，不承诺任意规模或 OS 级硬资源隔离。合成差分逐一与独立旧全量加密参考比较，不能替代形式化密码学证明。

## 免费预检与实际启动一致性

`production-startup-public-guard-v1` 将原离线固定诊断、分组策略/PM输出政策、步骤审计标识以及全部完整 v3 指令逐包抽出。生产启动和免费 API 预检复用同一函数与同一全代际加密凭据集合。

API 报告新增可选 `startupGuard={version, publicCollisionGuardVersion, ready}`，以及固定警告；失败返回固定 issue/unready 或保密边界通用400，不暴露私有统计/路径。报告 hash 包含检查结果和版本。纯报告构造不传服务回调时保留旧序列化/hash，旧预检原件不回写。

预检不解密、不持久化、不创建运行、不调用模型；ready不是付费授权或可消费启动 token。真实启动仍重复检查，后续新增数据/凭据或源码变化仍可失败，不能凭 ready 承诺完成业务交付。所有已创建失败尝试仍记录，不因费用0排除。

## 身份、复用与验证

启动身份动态纳入新的 server/shared 文件。Verifier对照当前固定 **study-selected** 源码集合升为 `verifier-study-source-v7` / 53文件，仅追加实际经 store 执行的新碰撞模块；不是递归完整 import graph、已加载TS字节、依赖安装或宿主环境的认证。历史v6/52及更早归档保持只读，不允许以旧缺项集合执行新实验。

新公共版本/标识均在 Agent 和 Jev 写入协议中保护，拒绝16字节以上凭据子串碰撞。工程代码、合成规模、启动同源与旧收据复核见 [本批验证](BATCH-HTML06-GUARD-CHECKS.md)；没有以工程夹具、前缀过滤或模型高分认定自主交付成功。
