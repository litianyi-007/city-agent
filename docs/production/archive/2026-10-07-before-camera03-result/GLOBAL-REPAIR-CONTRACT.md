# 生成前纠错与研发返修：共享有界闭环 v1

日期：2026-10-07。授权依据：用户“推进下一批”，在既有独立分支、权限和费用边界内实施。状态：工程验收通过，真实效果须另记，不能将工程夹具当自主交付。

## 目标与不变项

CAMERA-02 的测试角色在生成前输出非法 JSON，系统正确拒绝，但未将具体错误反馈给原角色。本切片让可修复的阶段失败进入内部闭环，而不是由外层开发修写模型产物。无需引入新的运行时或题目专用模板。

新策略 `production-global-repair-v1`：所有阶段重生成与最终 Gate 后的研发返修，共用用户冻结的 `maxRepairCycles`，上限仍为 2。首次生成不占返修额度；每次重生成前登记额度与反馈，计入原有请求、Token、时间和费用总预算。不是“每角色两次”或“结构两次加研发两次”。

HTML Prompt v5 / camera Prompt v4 用于新的配置版本；阶段 Verifier `verifier-phase-ordinal-v2`、最低评分、Jev 门限、acceptance 与最终 mandatory Gate 不变。旧实验、旧计数语义及冻结基线不修改。

## 状态与门禁

需求 → 产品 → 研究 → 项目计划 → 测试候选预检及质量评审 → 验收冻结 → 研发 → 真实行为 Gate → 项目反馈 → 交付。

任一阶段的可修复失败：保存拒绝 → 登记共享额度 → 给原角色具体反馈 → 原角色重新生成 → 原结构/质量门禁再验证。Gate 失败则保留原 Gate 和冻结 hash，按项目经理反馈由研发返修。最终通过不能仅来自 Verifier 的自然语言认可。

| 情况 | 动作 |
| --- | --- |
| 角色输出 JSON/schema 不合法；可判定的 CSS/测试契约预检失败 | 有额度才重生成，不自动修 JSON，不替换测试 |
| 协议合法的质量拒绝：LLM 弃权或 Jev 明确拒绝 | 有额度才将质量意见反馈原角色，重新评审；不强迫接受 |
| Jev 不确定 | 沿用一次 LLM 复核；仍拒绝才考虑共享重生成额度 |
| 最终 Gate 失败 | 保留失败，项目反馈决定返修或停止；返修也占共享额度 |
| API/授权错误、未知 usage、预算不足、运行/执行器总超时、取消、环境异常、非法 Verifier 协议 | 停止，不把系统/付费风险冒充可恢复质量失败；单业务断言等待失败仍可有限返修 |
| 共享额度耗尽 | 明确失败，保留全部候选和 Gate，不降门限或开启额外任务追通过 |

业务验收与测试契约仍须在研发前冻结。冻结前重新生成测试可以修复错误，但必须再通过同一 schema、预检和质量门禁；冻结之后不得修改测试、需求或 hash。

## 证据与兼容

新运行保存 `repairPolicyVersion` 与 `repairHistory`。历史每项包含：唯一 ID、时间、原阶段、角色、类型、全局序号、拒绝原因、候选引用、当时冻结 hash。阶段名不改成未登记 rubric；反馈作为 `context.regeneration` 的数据进入原阶段。完整原始输出仍在调用账本，反馈摘要有界且经脱敏，不暗改原文。

`repairs` 在新策略下表示全局消耗。无新字段的旧运行仍表示旧版研发返修，UI 明示旧语义；不回填不存在的历史，不重新解释旧实验。manifest、配置 hash 和 evidence 必须记录策略版本及明细。取消、重启仍不会自动重放收费请求。

## 本批免费验收

- 非法 Tester JSON 被拒绝；第二次是独立的内部角色调用，收到具体错误，再生成合法候选，重新验证后才冻结。
- 有效质量弃权反馈后重生成；被拒绝候选与原评审保留。
- 阶段重生成与 Gate 返修合计不超过 2；耗尽后不发第三次重生成。
- provider/未知 usage/非法评审协议/预算/取消不进入质量重试。
- 最终 Gate 的可信浏览器初始化故障及执行器总超时，须由控制面类型字段区分，保留失败 Gate 后直接停止，不询问项目经理再付费返修；不能依赖模型可伪造的检查名称/文本。普通 DOM 单条断言等待失败仍属于可返修质量缺陷。
- 验收冻结后 hash 和 checks 不变；不得删除失败测试或修写产物。
- UI 显示全局额度和两种返修来源，旧运行不被显示成新策略。
- 既有生产与虚拟社会工程/浏览器回归，独立目录与端口运行。

免费测试只证明控制逻辑与协议，不证明实际模型修复成功或成本收益。真实效果按 [CAMERA-03 预登记](CAMERA-03-PREGISTRATION.md) 独立记录。
