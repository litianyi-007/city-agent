# Verifier同条件候选对照评估计划

本文件仍是待冻结收费配置、待单独确认预算的计划。18个人工候选池已完成免费准备：36结构合法候选经实际Chromium，16通过/20预设业务负例，36/36标签一致，见[语料说明](VERIFIER-CHALLENGE-CORPUS.md)和[VERIFIER-PREP-01原件](experiments/VERIFIER-PREP-01/RESULT.md)。没有启动本对照计划的模型请求，也没有新增模型准确率、费用收益或自主交付实测值。文档版本不是已冻结的收费实验配置；[完整v1留底](archive/2026-10-07-before-verifier-corpus/VERIFIER-EVALUATION-PLAN.md)。

本批已实现 VE-02/03 的[注入执行器、独立初始manifest和先行intent账本](VERIFIER-STUDY-CONTRACT.md)，免费故障/取消/无缓存测试及真实Chromium Mock演练独立报告，不是本收费实验已执行。完成 VE-04 真实传输/配置预检和预算确认后，才登记新收费评估。当前任务预算不自动授权本评估；真正未见的真实任务继续留出。本次[完整v2留底](archive/2026-10-07-before-verifier-study/VERIFIER-EVALUATION-PLAN.md)。

## 1. 要回答的问题与证据边界

比较三个候选选择策略在同一冻结挑战集上：选对多少、错选多少、什么时候弃权，以及为这些决策增加多少调用、时间与费用。不把低供应商单价等同于已证明的高性价比，也不以该实验替代内部六角色从需求生成产品的真实交付。

本计划延伸[验收框架](EVALUATION.md)和[申报后清单](POST-SUBMISSION-PLAN.md)，与[旧实验账本](EXPERIMENTS.md)并列保存，不覆盖旧配置或旧结论。仓库没有配置kata Wiki，也没有`docs/lessons/`；历史关系在本文件显式声明，已参考[基线问题](BASELINE-AUDIT.md)。没有进行Wiki入库、跨目录扫描或自动归档。

截至本计划编写时，可用于设计反例的证据是：

- [现有基准](../../server/production/jev-benchmark.ts)只有三个人工待办池，每池一好一坏，比较Jev与首候选，没有单LLM或真实级联对照。
- 旧基准使用`phase='developer'`的whole-answer rubric；真实生产实施阶段为`implement`。新实验须显式使用新study版本和当前实施阶段契约，不能静默修改旧基准语义。
- CAMERA-01～05均为不同工程配置探索，原始run均failed、无最终冻结契约/最终Gate。它们只能提供缺陷来源，不能合并为固定配置成功率或当作五个独立业务需求。
- [CAMERA-05](experiments/CAMERA-05/RESULT.md)有11条预算记录、10次实际HTTP尝试；总usage/费用unknown，已报告小计不替代总额。平台传输阻断不是Tester或Verifier的业务误判。
- CAMERA场景Oracle只评价声明式配置及合成行为；真实视觉、实体设备、主观审美和完整摄像头需求不在本候选实验良品分子内。

## 2. 三个策略：只变决策，不变候选

| 策略 | 决策规则 | 每池最多评审调用意图 |
| --- | --- | ---: |
| A：无Verifier | 选预登记顺序的首个结构合法候选。仍执行相同最终Oracle/Gate，不允许错误产物绕过门禁。 | 0 |
| B：单LLM Verifier | 当前实际Verifier系统提示及schema；全部候选评分、最低3分、只选最高合格分，可合法弃权。 | 1次LLM |
| C：Jev级联 | 当前Jev三维/范围/Choice协议，最低3/4、集中度0.5；accepted选择，rejected不选择；仅uncertain或可信算术异常升级一次与B同配置的LLM。 | 1次Jev＋至多1次LLM |

所有候选先通过同一结构门禁；该主实验的候选都必须结构合法。结构非法、非法CSS、占位符、评分协议损坏等另外属于免费协议/预检反例，不混入主实验来夸大业务识别率。

本实验不生成候选、不调用产品/研发角色、不返修候选、不调整门限。一次LLM复核不能再复核自身的响应。unknown usage、取消、预算不足、传输错误、致命协议错误按当前生产规则停止，不用新模型、模板或Oracle答案代替。

“同条件”指候选、原始需求、冻结验收、可用事实、阶段责任、执行器及B/C复核LLM配置一致。Jev与LLM的API封装、系统提示和评分尺度并不相同；不能声称wire prompt逐字相同，也不能直接相减Jev的0～4分和LLM的0～5分。算术异常升级可以保留可信来源ID与受控诊断，但损坏分数、原始Jev意见和Oracle结果不得进入独立复核。

每个策略使用新会话、无跨策略答案缓存或先前意见。若将来研究复核缓存，须另列“缓存/反事实成本估计”，不能冒充本批独立调用结果。

## 3. 18池构成（已准备，不是收费实验冻结）

每池两候选；12个通用离线HTML池、6个受控场景JSON池。分层为8个一好一坏、6个双坏、4个双好，防止只在“一好一坏”里找明显错误。每池是独立需求/产物对，不复制旧三个待办夹具再改标题；但共享执行器及场景机制仍使池之间有关联，不能称为统计上的独立同分布样本。

| ID | 需求及拟冻结业务Oracle | 两候选构成 / 明确反例 |
| --- | --- | --- |
| H01 | 库存数量只允许1～5，提交结果精确反映数量，0与6拒绝且不改变库存。 | 好/坏；坏版接受0或超上限。 |
| H02 | 订单总额达到100才全单九折；边界100与多件60分别精确核算。 | 双坏；严格大于100才折扣 / 按单件价格判断阈值。 |
| H03 | 允许三位小数单价，单价×数量后统一舍入至两位小数；原数量保留。 | 好/坏；坏版先舍入单价而导致批量金额错误。 |
| H04 | 摄氏/华氏双向转换，0、负数及切换单位后结果正确。 | 双好；两种合法实现，避免偏好特定代码风格。 |
| H05 | 同日期同时间段不能重复预约，不同日期同时间段互不冲突。 | 双坏；允许重复 / 不同日期被全局时段锁误拦。 |
| H06 | 商品目录筛选后可恢复完整目录，切换条件不丢失原项。 | 好/坏；坏版筛选破坏原数组。 |
| H07 | 多题单选问卷各题独立，改选后计数与提交答案重新计算。 | 双好；不同合法DOM结构，使用各自冻结且等义的业务定位。 |
| H08 | 测验成绩由当前答案重算，重复提交及改错不积累旧分数。 | 双坏；重复累加 / 修改答案仍保留旧分数。 |
| H09 | 工单流转后卡片状态与分类数精确一致，往返流转无丢失。 | 好/坏；坏版仅更新卡片或只更新分类统计。 |
| H10 | 两个同名采购项有独立ID，删除一项不影响另一项，连续删除不误删。 | 双坏；按名称批量删除 / 使用失效索引删除错项。 |
| H11 | 支出分类汇总精确到分，新增/删除后分类与总额一致，拒绝空或负值。 | 双好；合法等义实现，不以代码相似度定义质量。 |
| H12 | 多步骤表单重置后字段、进度与最终提交数据都回到初态。 | 好/坏；坏版只清展示，提交仍使用残留状态。 |
| C13 | 明确张掌scatter、握拳gather、横移rotate，固定标签与行为保持一致。 | 好/坏；坏版反向映射，虽schema合法仍不满足需求。 |
| C14 | 横移必须旋转，并保持原先明确的掌/拳动作。 | 双坏；关闭横移 / 开启横移但反向掌拳。 |
| C15 | 初态有可见几何主体和雪，原配置及无雪派生诊断均应显示主体。 | 好/坏；坏版主体完全裁剪，仅雪或背景可见。 |
| C16 | 无雪场景总粒子精确180，初始主体可见，聚散不改数量。 | 双好；两种满足明确配置要求的布局，不评价主观审美。 |
| C17 | 明确要求同时有cone及star，二者有非零粒子并在初态可见。 | 双坏；分别遗漏一种。须有独立字段谓词及像素/行为验证，不能仅引用generic Gate通过。 |
| C18 | 主体160＋雪20，总数180，精确标题与动作映射保持。 | 好/坏；坏版忽略雪计数或给出错误总量。 |

上表不是已冻结收费测试。准备已补足精确输入、边界、允许等义实现与断言；36/36标签核对不是36候选全通过（实际16通过、20失败），更不是模型选对36次。同池统一中立DOM，不需要候选特有定位；H07等义实现与H10中间数量边界已实测。C17在准备前明确左cone/右star无雪布局，同时检验原画布两侧像素与逐primitive派生，不能只引用generic Gate。具体源码与hash见准备manifest，不把后续模型结果用于重新贴标签。

一好一坏池的首位在冻结前分层平衡：四池首位好、四池首位坏；双好/双坏池内部顺序以固定种子打乱。由此构成的基线比例是人为设计结果，不是自然分布中的产品成功率；实际结果仍须逐候选运行Oracle，不能按构造标签直接填入Gate通过。

## 4. 独立Oracle与冻结要求

Oracle是独立于评审模型的业务判定，不是LLM自述。免费准备阶段先用已知输入验证所有好/坏标签，再冻结；收费评估时先完成三个策略的选择，再对全部候选执行相同Oracle并保存实际结果。准备验证记录与正式测量记录分开，不称“从未看过数据的随机测试”。

HTML Oracle使用实际Chromium交互、精确输出/元素数及边界状态。场景Oracle使用严格schema、当前mandatory Gate、冻结业务CSS和必要的场景字段谓词。新增谓词只属于基准，不是题目关键词分支或对生产Gate能力的冒称；未实现谓词时，对应池不得进入冻结批次。所有执行沿用现有受限环境，无宿主生成Node/shell、无相机授权、无外网资源。

构造者不得单独决定标签：至少一份独立复核检查需求、标签和Oracle是否一致；实际由人或外层开发Agent复核如实登记，不把两个Agent写成双人工标注。标签有争议、Oracle覆盖不足或依赖主观审美的池在冻结前替换/澄清；冻结后不能看模型结果再重新贴标签或删样本。

正式冻结manifest至少包含：

- study/pool/Oracle版本、18个固定ID、分层、固定顺序及随机种子、候选原字节hash、人工构造来源与许可。
- 需求原文/验收/能力profile、场景显式映射、业务Oracle定义/源码/checks hash、schema/语义/覆盖责任版本。
- 当前源commit、Prompt、Verifier与compact策略、Jev数值/请求layout版本、Harness literal transport版本；Gate源hash、runtime/资产manifest/hash及browser版本。
- B与C复核的Provider/Base URL/Model ID及可观察响应身份限制；所有实际模型参数，不支持或未报告参数标为provider-default/unknown，不猜测已冻结temperature。
- 每策略/每池/整批的调用意图、Token、时间、金额限额与价格适用口径；不保存Key，只保留安全配置状态。
- 独立标签及Oracle准备记录的hash。公开评分请求可携带原始需求、合法冻结验收与覆盖事实，但不含好坏标签、缺陷描述、Oracle执行结果或其他策略意见。

36份候选源码不能出现“正确版/错误版”等提示性标签；源代码注释、名称与篇幅不能成为明显答案泄漏。标签及缺陷元数据留在评估控制面，不放入候选序列化请求。所有JSON/Schema保留实际严格字段；不能通过脱敏保留值碰撞改写rubric。

## 5. 免费预检、费用与停止规则

计划最大为A零调用＋B的18次LLM＋C的18次Jev与至多18次LLM＝54个评审调用意图。它不是实际HTTP尝试硬上限，也不是54次一定发生的付费请求；Harness实际wire尝试、模型usage、未发POST意图和失败请求分别记录。新study的整批限额不冒充现有生产单任务的默认调用限额。

实际价格、输出/输入上限和整批金额尚未批准。准备完成后一次性提出模型配置、估算依据、每池与整批硬预算，由用户另批确认。按当前控制面保守预留方法估算，不能用历史平均Token代替上限；B/C独立LLM输出预留、Jev实际输出Token及免费输出价格口径也须明确。不能为凑54次而放宽unknown停止或追加额度。

免费预检必须通过：

1. 36候选结构合法，实际Oracle与标签一致；全坏/双好/数值边界的判定有独立反例。
2. 所有真实传输请求离线序列化测量，角色/Verifier上下文、Jev单题32KB及整批64KB等当前边界都满足；不截断、不删业务要求。
3. 一次复核和来源链正确；早算术异常之后的致命错误不能被掩盖；非法协议不变为accepted或合法弃权。
4. 双坏无默认首候选/模板回退；候选、检查、配置hash不能在评估/执行钩子中改变。
5. 初始快照、每次请求intent先持久化；取消、超时、unknown、费用/Token停止和重启不漏账、不自动重放付费调用。
6. 注入LLM/Jev和本地fake provider测试标注工程证据，不能填入真实效果分子。

依次运行所有池，三个策略的执行顺序在冻结时交错固定，避免人为挑选后运行顺序。每个策略使用新会话和原始候选，无前一策略反馈。遇到unknown/安全故障时停止后续收费，保留已启动和未启动项及原因；不靠其他策略的历史输出补齐结果。

## 6. 分层指标与分母

主报告展示每池×策略的逐项结果，不只给一个综合分数。

| 指标层 | 必报指标 | 避免的误读 |
| --- | --- | --- |
| 协议 | 合法JSON/字段/ID/最低分/最高分选择；非法协议、算术异常、传输错误、unknown usage、取消分别计数 | 长度违约不是合法弃权；格式合法不是业务正确 |
| 业务 | 选中好候选数、选坏数；6个双坏池中的误选择；12个有好候选池中的合法弃权与错选 | accepted后实际Oracle失败为业务误判，即使最终Gate阻断交付 |
| 覆盖 | 选择率、选中好候选/计划池数、已选择且Oracle已知的条件正确率 | 条件正确率不能省略弃权/错误，未执行Oracle不当作已知错误 |
| 对照 | 对A、对B分别记录改善/退化/相同/合法弃权/协议失败/未知的配对表 | 不把失败、skip统一写成“保守弃权” |
| 成本 | 实际wire尝试、评审intent、输入/输出Token、声明价估算、总/每池墙钟、复核次数和升级率 | unknown保留；价格估算非发票；外层准备/Oracle成本另列 |

完整批次主分母固定18池/策略，另列attempted、selected、Oracle-known及各分层分母。因停止而未启动项保留not-started；“已知好选择数/18”只能作为完成结果的保守比例，不把缺失结果推成某策略的真实判断准确率。配对分析必须列明缺失，不仅挑两个策略都成功的池。

保留Jev原始序数分布与集中度、LLM原始序数与原因，作为诊断数据；集中度不是答对概率，本实验不声称概率已校准。可报告模型意见错误类型，但不因其理由写得可信就覆盖独立Oracle。

费用可报告每个已知正确选择的成本；分母为0时undefined，含未知用量时总成本unknown，已报告小计另列。人工耗时没有同范围实测时仍为unknown，不以人日预测计算“增效几倍”。

不预登记必定“Jev优于LLM”。效果决策条件应在VE-04冻结：是否增加已知好选择、是否引入更多错选、是否真正减少LLM用量，以及新增Jev费用后总成本是否下降。任何优势只按此次冻结人工挑战集表述；小样本即使出现改善，也不报告显著泛化收益或通用可靠性。

## 8. 后续材料可以如何表述

现在可以写：“已具备独立Verifier、托管Jev级联和可追溯硬Gate；18个人工挑战池的36候选已完成免费独立Oracle准备，同条件三策略注入执行器与先行账本已实现，真实模型对照待传输、正式配置冻结与新预算确认。”

未来实测后可以写：“在某冻结版本的18个人工挑战池上，三策略分别取得X个已知好选择、Y个误选择、Z个合法弃权，实际费用/已知小计及未知项如下。”同时列明来源不是内部Agent生成、设备层未验证及样本构成。

不能写：“18个真实需求自主交付”“验证通用L4/L5”“Jev概率已校准”“所有模型都更准确/更便宜”“三策略条件正确率证明整体成功率”“AnyJev SDK已实施”。本实验未实施AnyJev；它仍是未来本地typed decision/分级决策研究，不与软件自动化L4/L5等级混用。

通过该评估也不等于通过真正未见任务。受控仓库、实体摄像头、固定配置多次真实交付及同范围人工效率对照仍按各自后续任务单独验收。
