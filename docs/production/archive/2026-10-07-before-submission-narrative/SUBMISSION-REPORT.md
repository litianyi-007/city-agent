## 2. 管线设计、人工边界与复用

```text
用户：目标/范围/模型/预算授权
  → 产品经理扩展目标 → 研究员核对约束 → 项目经理设计任务
  → 测试生成验收 → 结构/选择器预检 → 冻结版本与 hash
  → 研发实现 → 候选验证 → 确定性浏览器功能 Gate
  → 通过：源码/截图/证据包；失败：反馈 → 项目经理重规划 → 有限返修
  → 超时、取消、超预算、协议错误：明确停止，保留失败与已知费用

各阶段候选：实际 schema 预检 → Jev 快速决策或独立 LLM Verifier
                                    ↓ 不确定/受限算术异常
                              原预算内一次独立 LLM 复核
模型配置和 Key：控制面；产物/浏览器：执行面；账本：保存两者的可观察证据
```

| 环节 | AI 职责 | 门禁标准 |
| --- | --- | --- |
| 产品 | 扩展原话为目标、用户故事、范围、非目标与验收 | 实际版本化结构契约有效；不得把业务必需项偷偷改成可选项。 |
| 研究 | 核查约束、风险与实现选择 | 已知/推断/未知分开；不扩大工具与网络权限。 |
| 项目管理 | 思考摘要→设计→实施→测试→反馈→再设计；跟踪任务与额度 | 可观察决策，明确终止；生成前纠错与研发返修共用最多两次，不无限循环。 |
| 测试 | 生成可执行浏览器检查并判断结果 | 研发前预检并冻结；合法选择器不是业务覆盖充分的证明。 |
| 研发 | 按冻结目标与契约生成产物、根据失败证据返修 | 不得改 Gate、删除断言、使用人工修改或模板回退冒充真实通过。 |
| Verifier/Jev | 按细粒度 rubric 检查本次候选池，选优或弃权 | 非法输出/未知费用/错误 ID 不默认接受；模型意见不能覆盖硬 Gate。 |
| 确定性 Gate | 实际页面操作、精确结果检查；摄像头场景另有必需行为校验 | 不是“返回测试通过”的文字；真实视觉、实体设备与合成行为分别记录。 |
| 交付 | 汇总输入、模型/Prompt/版本、全部请求、契约、源码与结果 | 失败、取消、截断、未知均保留；产物与来源有血缘。 |

人工负责初始目标、权限、配置、预算与最终采用；有风险越界或关键信息缺失才请求选择。运行中的人工改产物/改 Gate 必须计介入且不能算无人自主交付。平台开发者在不同实验之间修复平台是外层工程，不等同单次内部 Agent 自主返修。空的介入数组只证明系统内未登记介入，不能证明系统外无人操作。

复用采用版本化角色输出、统一模型配置、验收冻结、预算/取消及证据协议，不为某个演示词新建硬编码产物。Mock 固定夹具另有明确模式和来源标记。后续受控仓库扩展复用本状态机，但必须先验证容器隔离，不能直接在评委宿主执行模型脚本。Worktree 是开发隔离，不是安全沙箱；现有受限 Chromium 的防护不作“任意恶意代码完全安全”保证。

## 6. Verifier、Jev 的创新、缺陷归因与改进

高质量/高性价比的核心是“生成和验证职责分离”，不是让生成模型自己说成功。参考 [LLM-as-a-Verifier](https://github.com/llm-as-a-verifier/llm-as-a-verifier) 的细粒度评价/反馈思路，实现角色候选的结构化序数 rubric、合法引用、接受/拒绝/弃权与返修反馈。多候选仅在预算允许时使用，不声称本项目复现其训练、score-token logprob 或 tournament 方法。

托管 [TypeSafe Jev](https://docs.typesafe.ai/introduction/coding-agents) 已实际接入决策设置、加密 Key、Score/Noul/Choice 评审、独立费用账本与 live 不确定升级一次 LLM Verifier。它是结构化决策层，不替代代码生成 LLM。当前 `jev-candidate-v3` 在完整协议预检后，只有已分类的派生算术漂移可以弃用 Jev 决策并进行一次独立复核；非法模型/ID/问题全集/概率/usage 仍硬停止，原始响应不归一化、不改写为通过。

合成候选池 v2 的三题中，首候选 Gate 1/3；含弃权的选中率2/3，选择覆盖率2/3；已选择条件通过2/2。样本是人工构造、不是随机真实需求，不证明普遍成本降低、概率校准或端到端良品率提高。CAMERA-04 没触发算术漂移，仅观察到三次正常不确定升级；v3算术分支只得到免费工程夹具验证。

参考 [AnyJev](https://github.com/nokia-applied-research/AnyJev) 的 typed decision 与能力分级，下一步研究 retry/replan/terminate 等低风险决策的可替换适配器；**本地 AnyJev SDK 未接入**。托管 Jev 已实施不等于 AnyJev SDK 已实施；其决策能力分级不等于研发 L4/L5。校准需要独立标注集，不能从本轮小样本或“confidence”字段推导可信正确率。

当前致命缺口及后续顺序：

1. CAMERA-04 Verifier 完整返回的一个 `reason` 长1428字符，超过冻结1000上限，整条决策被合法拒绝。计划指导紧凑输出而非裁剪旧原文或放宽旧 Gate。
2. 测试候选含未展开 `{{particleCount}}` 和“散开应改变粒子总数”的语义矛盾；CSS语法合法不等于业务正确。计划增加未解析占位符/不变量冲突的生成前预检和原测试角色有限纠错。
3. 明确平台场景 schema、必需几何行为、CSS角色验收、真实视觉、实体设备的覆盖责任；避免 Verifier要求 CSS检查无法观测的内部数据，或过早夸大覆盖。
4. 先免费负例/闭环验证，再冻结新配置与 CAMERA-05 预登记；保留所有旧负结果，不临时重定义成功。
5. 真正最小真实闭环通过后才开启两公开任务+一未见任务各三次的预登记稳定性实验。建议8/9且每类≥2、安全硬门限全过；九次也不证明通用可靠性。

业务价值是降低单人把模糊目标转成可测软件的协调成本、让失败可定位并复用证据；目前为可运行管线与决策层的阶段技术价值，尚无已实测商业增效。环境现实映射、居民记忆/wiki/dream属于并行虚拟社会线的规划，不作为本线已实现创新。

## 7. L4 自评与推广

按操作性定义：六角色配置、可观察流程、验收冻结、预算/取消、失败留痕及可信 Mock 已有工程证据；真实模型一次完整交付的最低门槛尚未满足，容器/任意仓库、稳定性、≥3真实业务需求、人工同范围增效对照均未完成。因此自评为“有界自主研发 Demo，未达到最小真实闭环验收”，不作官方 L4 认证或稳定通用 L5 声明。

推广先向小型无网络页面/严格场景数据任务开放，要求使用者自备 Key、有限预算与明确验收；真实运行可能失败。待受控执行环境和独立任务基准过门禁再扩展仓库。材料可转发，但禁止转发 `.city-agent-production`、加密主密钥、配置库或任何 API Key。

## 离线与在线材料的协作规则

- 离线 MD/PDF：完整七栏目、结论、限制、费用、安装指南索引，评委断网也能读懂；ZIP同时包含视频与原始证据。
- 在线版本页：同版 MP4播放、可信 Mock交互、原始JSON/源码文本下载、安装命令和材料hash，丰富证明形式，不产生新的真实交付结论。
- 区分执行 commit、报告/发布 commit、材料版本和文件hash。新材料可以补充旧原始证据，但不能把新版本元数据回填旧实验。
- 最新入口只导航；正式提交使用本次包给出的版本URL，并保存完整ZIP。外链不可访问时仍可离线审阅，不把链路可用性当项目能力证明。
