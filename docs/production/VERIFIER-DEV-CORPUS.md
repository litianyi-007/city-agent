# Verifier 开发语料 v1

本切片实现三个人工构造开发池、六份完整 `{html}` 候选和同池共享的中立 DOM/精确行为 Oracle。它们只用于免费工程预检和以后开发调优，**不计入正式18池、不是真实业务需求或内部 Agent 交付，不提供模型准确率/高性价比证据**。正式评测仍按 [Verifier 对照计划](VERIFIER-EVALUATION-PLAN.md)另行准备、冻结及确认预算。源码未接入生产需求关键词分支或六角色编排。

当前状态：2026-10-07专项4/4通过、26.788秒；六候选的实际浏览器Oracle逐一与构造标签一致，TypeScript检查通过。没有启动供应商请求。此工程结果不代表任何模型已正确选择候选。

## 开发池与业务判定

| 池 | 需求 / 精确边界 | 控制面预期构成 |
| --- | --- | --- |
| DEV-01 | 0–1439 整数分钟转 HH:MM；0、59、60、65、1439，非法输入保留结果，重算与重置 | 一坏一好；小时向上取整 / 向下取整 |
| DEV-02 | -50–50 整数闭区间求和，含两端点；单点7、2..4、跨零区间，倒置/越界/非整数拒绝 | 双坏；分别遗漏上、下端点 |
| DEV-03 | 0–9999 整数各位数字求和；0、909、1000、9999，非法输入、重算与重置 | 双好；逐位字符串 / 整数取余两个等义算法 |

三池共用 `#input-a/#input-b/#calculate/#reset/#result/#message`；不用第二输入时其容器隐藏，但元素保留。同池候选的 DOM/CSS/界面文字一致，不为某一候选换更容易的定位。Oracle只使用普通 CSS、真实fill/click、结果/错误精确文本与重置值，不用模型自述或静态“通过”文字。

外层开发 Agent 构造语料；独立审查是外层工程审查，不应冒称双人工标注。候选真实行为只有在请求拒绝、独立 Chromium `runGate` 实际执行后才确定；环境故障必须报告为工程失败，不能改贴坏标签。分钟与区间边界分为独立新页面检查，避免首个失败使后续数值边界根本未执行；一个检查内部仍会在首个失败处停止，不声称失败后的步骤已运行。每候选原始实际 Gate、预期、HTML原字节/检查JSON hash 都作为测试 diagnostic 输出，保留在该次原始测试日志，不混入评审请求。

## 文件职责与泄漏边界

- [语料](../../shared/production-verifier-dev-corpus.ts)：严格HTML候选、冻结检查、中立DOM；`VERIFIER_DEV_EXPECTATIONS`是单独的控制面gold/缺陷元数据。
- `verifierDevReviewSnapshot`只按白名单序列化原需求、完整候选、人工先验阶段上下文和冻结检查；递归冻结，不能携带gold、缺陷、Oracle结果、旧Jev意见或其他策略意见。候选ID无好坏暗示，候选源码无正确/错误版本注释。
- [专项测试](../../tests/production-verifier-dev-corpus.test.ts)：实际schema、不可变性、泄漏反例、当前 `phase=implement` rubric和请求大小，以及六候选实际业务Oracle。

评审上下文中的产品/研究/计划是明确标注的人工夹具，不是伪造的自主角色输出。完整冻结验收本身可以进入评审；实际Oracle结果及构造缺陷不能进入。源文件公开意味着开发池不再适合充当未见集；未来正式18池仍需独立建设及盲评配置。

没有新增第三方依赖或新供应商schema。测试复用现有Zod `codeSchema/testsSchema/verifierSchema`、阶段rubric、coverage和Jev请求构建器；源码只引用共享coverage，未引入后端到浏览器包或新增平台运行时。

## 免费门限与结果口径

1. 六候选均通过同一严格 `{html}` schema、各池全部行为检查通过现有测试schema；好坏差异只能是业务行为。
2. 六份真实Chromium结果必须与控制面预期逐一一致；失败检查原样留在日志。无相机/麦克风、外部模型、宿主生成脚本或服务启动。
3. 完整两候选、原需求、冻结检查和当前implementation上下文不截断；Jev每题 `state + 最大question ≤ 32000 B`、整请求 `≤64000 B`。复用真实构建器，字节不是估算Token。
4. 同时测当前Verifier系统提示与按当前criteria字段/实际版本构造的开发合成用户逻辑Prompt合计 `≤60000 B`；人工上游上下文不是某次真实生产运行的完整wire复现。这不是SDK HTTP包或真正模型Token测量，也不把纯序列化写成真实请求。未调用Harness或JeV端点。
5. 不修改生产门限、Gate、旧实验/申报附件或正式18池；当前结果只证明工程预检。以后若评估A/B/C，最多3次B的LLM、3次C的Jev和至多3次C复核（9条意图），仍须另批预算；本切片未启动该评估。
