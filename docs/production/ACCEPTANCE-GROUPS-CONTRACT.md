# 版本化验收规划与分组生成

日期：2026-10-08。分支：`feature/autonomous-production`。这是免费工程改进，不是新的真实模型实验，也不追认 HTML-03／HTML-04 成功。

## 为什么改

[HTML-04](experiments/HTML-04/RESULT.md) 首份测试结构合法但原始业务覆盖不足；后续 JSON 错误及单项超过20步耗尽两次共享修复。新的通用方案先形成可审查的条款／状态／检查槽位，再生成较小片段，最后对完整候选独立审核。不按费用页关键词产生代码或断言，不修补旧实验产物。

## 启用与兼容

在本地 `http://127.0.0.1:4420/#production` 的“新建自定义需求”中选用“启用分组验收规划（工程预览）”。默认关闭。字段 `acceptanceStrategy: planned-groups-v1` 只允许真实模式、离线单 HTML、LLM Verifier、单候选及 legacy 实施证据策略。双候选、Jev、source-bound、摄像头或 Mock 的组合明确拒绝，不自动改模型、权限、预算或策略。

未传新字段的旧流程、旧配置版本及历史原件保持不变。免费预检展示兼容性与调用包络，不授权调用；切换策略撤销已有启动同意。真实模式启动仍需页面 Key、费率、干净源码／匹配构建及新的单次预算。

## 唯一执行链路

需求 → 产品及独立审核 → 研究及独立审核 → 项目经理规划及独立审核 → 验收计划及独立审核 → 测试分组生成 → 完整结构／语义／CSS预检 → 完整独立 Verifier → 冻结 → 研发及独立审核 → 实际浏览器 Gate → 项目经理反馈及独立审核 → 交付。

| 环节 | 约束与门禁 |
| --- | --- |
| 验收计划 | PM 输出原话精确引用、条款、状态、预期、setup／exercise／assertions及步数预算；原始 brief 与 acceptance 均须引用，条款和槽位引用必须闭合 |
| 分组 | 1–3组，每组1–4个预登记槽位，合计2–12项，每项预算1–20步；组顺序、槽位顺序、数量及 ID 精确匹配 |
| 构建绑定 | 每份响应绑定计划 SHA-256、groupId及本轮 attemptId；旧轮次、未知槽位、错序、超预算或额外字段拒绝 |
| 无损组装 | 只去除协议包装，不排序、裁剪、改写、规范化或修补模型测试；保留各组原始响应与哈希；沿用原完整 Gate schema |
| 完整审核 | 组不分别“通过”；完整候选必须结构／语义／Chromium CSS预检有效，再由独立 LLM 按原始需求复核全部状态、边界、负例和独立 setup |
| 冻结与执行 | 审核接受后一次冻结完整检查及构建血缘，研发／返修不得修改；最终交互 Gate 不被 Verifier 的文字接受替代 |

精确引用、ID完整及静态审核只说明血缘和候选质量，不证明所有业务已经覆盖，也不证明功能行为正确。最终成功仍要求生成代码通过预先冻结的实际浏览器 Gate；生产控制面仍不执行生成的宿主 Node／shell。

## 修复、停止与取消

- 全链路继续共享最多两次自动修复，不为分组另建额度。
- 当前组 JSON／契约不合法：仅重生成同一计划、同一组、同一构建轮次，保存失败原文；先前合法组保留。
- 完整结构／语义／CSS拒绝或完整 Verifier 弃权：消耗一次共享修复，开启新 attemptId，全部组重新生成；旧轮次原件保留，不能拼入新轮次。
- unknown usage、传输错误、Verifier协议错误、预检基础设施异常、来源漂移、取消或时限触发：停止，不包装成候选质量返修。取消后的迟到成功响应不得触发冻结／开发。
- Key 与固定协议、诊断或完整指令冲突：付费请求前拒绝。各完整指令分别执行已有有界凭据碰撞检查，保留每次100,000工作上限，不省略文字、不读取或输出明文 Key。

## 调用与费用口径

单候选、无返修时：一个组14、两个组15、三个组16次逻辑模型调用。预检保守展示初始16次、最坏 `16 + 6 × maxRepairCycles`，两次修复时28次；包括项目经理前置重规划的上界，不表示每次都会用满。

用户 maxCalls、Token、时限、声明价预算不会自动提高到该包络。若用户仍设置24次，预检提示不足以覆盖28次最坏包络，执行在原硬门限停止。请求次数与供应商账单不能混同；unknown费用不记为零。片段更小不等于总成本更低，增加的计划／完整审核成本必须在新真实实验中计入。

## 版本与证据

- 策略：`planned-groups-v1`
- 本策略调用 Prompt：`production-html-grouped-v1`
- 计划／组／构建：`production-acceptance-plan-v1`／`production-acceptance-group-v1`／`production-acceptance-construction-v1`
- 旧 HTML v11／摄像头 v7、完整 acceptance v3及旧 rubric 阶段不回写；新增 acceptance-plan 使用专门评审形态，不要求普通 PM decision/tasks 字段。

`acceptanceConstruction` 保存：计划源 callId／candidateId、原始响应及值哈希；每轮开始／结束／决定／错误；所有启动的分组调用 ID；每个合法组来源和值；完整检查哈希；完整审核调用 ID。聚合候选使用独立 UUID，不伪造一次模型调用。证据 JSON 与交付 manifest 包含该记录，冻结 hash 包含其血缘；实际模型调用、用量与费用仍只按 calls 统计。

运行时源码闭包包含新 server／shared／src 文件；本策略不冒充旧 Verifier study 的独立源码闭包。新能力不修改主线、冻结 Tag、已申报原稿、公开 v6 或旧实验。

## 工程与真实验证分开

模块、注入式管线、免费 API／预检及浏览器交互夹具覆盖协议、预算、血缘、拒绝、共享修复、取消及兼容；夹具 Verifier 接受和假 usage 不计真实交付或经济效益。具体结果见 [本批记录](BATCH-ACCEPTANCE-GROUPS-CHECKS.md)。

下一次真实尝试需新预登记及单次授权，固定原始需求、该策略／Prompt／模型／预算与验收口径；HTML-04的一次授权已经结束。失败、取消、截断均入账。工程通过后也只能说本策略可运行、待真实模型效果验证，不能宣称稳定通用 L5。
