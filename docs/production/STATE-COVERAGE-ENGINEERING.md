## 可见 DOM 与压缩依据

- `#ledger` 是用户实际看到的业务明细列表，每个 `.record` 直接显示描述、分类及两位小数金额；不含删除按钮、输入回显、隐藏摘要、hash 或通过标记。删除操作位于独立 `#operations`。
- `#feedback` 是用户可见的反馈区，直接显示本次错误（如有）、全部总额和当前筛选小计。用一个精确文本断言同时检查两项金额，不省略任何统计。
- 分类默认办公，有可见说明和选中状态；某些正向 seed 可省去重复点办公。每次负例仍重新填写其它合法字段并显式点击办公。
- 编辑字段清除旧反馈。每次拒绝使用原有 `assertChanged(#feedback, after.click #add)` 实际提交，再验证反馈可见、实际条数、原业务明细、错误与双统计。嵌入的 click 本来就属于一个外层步骤，不改 schema，也不是把伪操作算成完成。

一次负例为8步：填描述 → 点分类 → 填金额 → 上述真实点击/反馈变化 → 反馈可见 → 数量精确 → 业务明细精确 → 提示与双统计精确。已有态先独立新增 seed 共4步，所以两次负例恰为20步。不能用单独 changed、静态提示或末尾一次统计替代逐次业务断言。

## 三类证据不能混用

1. **结构/容量/来源**：原 `testsSchema`、CSS与语义预检、分组组合和步骤审计原样使用。3组按注册顺序无损组合；来源/hash/轮次/顺序/预算篡改、21步/13项/4组拒绝。夹具 UUID/hash 是合成绑定，不是模型调用认证。
2. **工程行为**：手写可信 HTML 在未改动的受控 Chromium Gate 中，正序和反序均实际执行12项，另独立检查真实可见 DOM。36个行为 mutant 各跑受影响原 check＋另一个独立原 check，并要求受影响项失败；不是每个 mutant 都跑12项。覆盖静默接受非法金额、边界拒绝、浮点/拼接、隐藏提示/明细、陈旧提示、内容/分类/金额/统计破坏、筛选/删除错误和首轮破坏后恢复。
3. **真实生产**：尚需内部产品、研究、PM、测试、研发、Verifier真实调用，自己生成并冻结契约，再通过行为 Gate。手写 HTML/checks 不传入下一实验、不注册为产物或内部候选，不计良品分子。

五种故意弱测试（少填其它合法字段、漏内容/统计、跨项借状态、仅最后负例断言、少单次提示）仍可通过结构/步骤审计，这一机械边界有明确回归，不包装为“自动语义覆盖认证”。有限 mutant 集不证明抓住所有缺陷；`innerText`/DOM 数量本身也不是任意页面所有节点可见性的证明。本夹具另有显式可见性断言和结构检查，但不声称形式化完备。
