# VERIFIER-REAL-01 Jev 数值兼容核对与免费重放

日期：2026-10-08（UTC+8）。本页只核对已付费、已失败的 [VERIFIER-REAL-01](experiments/VERIFIER-REAL-01/RESULT.md) 三份原 Jev 响应及 `jev-candidate-v3` 数值校验。没有新增供应商请求、LLM 升级请求、Oracle 或正式质量样本，也没有重试、恢复或改写原实验。本批实现不更改 Jev 数值公式、±0.005 假设、3/4 评分门限或0.5集中度门限。

免费重放仍为 H01/H02 `error/arithmetic-drift`、H03 `uncertain`，没有直接接受。四项集中度冲突可用独立代数证明，结论是**原返回字段不能同时满足当前冻结兼容假设**；这不足以确定供应商内部实现错误。返回集中度反映决策分布的集中程度，不是软件需求满足率、业务正确率或交付成功概率。独立行为 Gate 仍须执行。

## 来源与兼容前提

本页于2026-10-08读取 [TypeSafe HTTP API](https://docs.typesafe.ai/api) 与 [Confidence](https://docs.typesafe.ai/confidence)。前者支持响应 model、question ID、Score 的概率加权均值、Choice 的最高概率选项和 usage 字段；后者给出从完整分布计算集中度的公式。它们是当前公开资料，不是原付费时刻的不可变文档快照。既有 [2026-10-07独立语义核对](JEV-SEMANTICS-REVIEW-2026-10-07.md)另列官方 SDK、模型限制及 AnyJev 语义边界。

| 项目 | 供应商公开语义 | 本地被冻结的兼容检查 / 未决边界 |
| --- | --- | --- |
| 五级 Score | 等级索引0–4的概率加权均值 | `μ=Σ(i×p_i)`；所有 rubric 标签、回答ID与候选ID必须匹配。 |
| Score 集中度 | 按众数 m 的绝对距离相对于均匀分布到中间等级的平均绝对距离计算，最低0 | `C=max(0,1−Σ(p_i×\|i−m\|)/1.2)`；1.2为五级均匀分布相对等级2的MAD，不是可调容差。 |
| Choice 集中度 | 最高概率相对 n 项均匀概率的超出比例 | `C=(p_max−1/n)/(1−1/n)`；本批 n=3，包含 `abstain`。 |
| Noul | 单一 yes 概率，无独立 confidence 字段 | 以 `\|2p−1\|`使用同一集中度门限；不将 p 当业务正确率。 |
| 概率和与显示精度 | 文档要求概率和为1，示例显示小数 | 每一概率、score、confidence 独立允许±0.005，并要求存在**同一**概率和为1的分布支持它们；这是假设最近舍入到两位的本地兼容协议，不是已核实的供应商精度承诺。 |
| 众数并列 | 官方示例代码取第一个最大值 | 现校验检查可行的显示并列众数；本批四项异常均唯一众数，不依赖这个差异。 |
| 派生顺序 | 已查看页面未承诺序列化精度或派生顺序 | 是否从隐藏精度或显示概率计算、最近舍入/截断规则、端点舍入和并列规则仍待确认。不能用更大容差填补。 |

本地 `1e-9`只处理数值求解误差；不是扩大±0.005范围。独立区间、归一化概率、只检查显示均值或者用本地重算字段替换原返回值，都不能证明当前要求的联合兼容性。当前路径没有这些替代操作。

## 四项冲突的独立证明

下表直接来自原公开账本的 `rawResponse`；显示概率复算值仅用于诊断，不回写供应商字段。

| 原事件 / 字段 | 返回 score / C | 显示概率复算 μ / C | 唯一众数 | 固定±0.005下的正间隙 |
| --- | --- | --- | ---: | ---: |
| event10 / H01 / c0_coverage | 3.40 / .52 | 3.42 / .516667 | 4 | .013 |
| event10 / H01 / c0_consistency | 3.48 / .54 | 3.45 / .541667 | 4 | .021 |
| event22 / H02 / c0_coverage | 3.37 / .46 | 3.35 / .458333 | 4 | .007 |
| event22 / H02 / c1_consistency | 1.30 / .57 | 1.33 / .575000 | 1 | .015 |

前三项在真实概率和为1、众数为4、C>0时必有 `μ=2.8+1.2C`。同时允许 score、C 各±0.005后，两个必要均值区间仍不相交；正间隙分别为.013、.021、.007。第四项众数为1时必有 `μ=2.2−1.2C−2p0`；再允许 p0±0.005后，隐含均值区间为[1.320,1.352]，原 score 区间仅[1.295,1.305]，间隙.015。这些必要条件独立于现有联合多面体求解器。

H03通过结构及数值联合校验，但两个候选都未达到全部冻结门限。`cand-80c4`的 coverage 为2.99、集中度.16；Choice 集中度.56不能弥补候选维度不足。因此是合法 `uncertain`，不是算术错误或直接接受。

原响应hash固定的是账本中的JSON对象序列化；账本没有保存原HTTP响应的空白格式与独立线缆字节，不能把该hash称为HTTP原字节hash。请求hash分别区分 call-intent 的候选上下文和实际 Jev 完整请求；测试还核对候选value hash、完整业务材料、原观察绑定、模型ID和usage。hash完整性不是可信签名或业务正确性证明。

本批提示改进将共享阶段rubric从原 `verifier-phase-ordinal-v4`版本化为v5。因此现有请求构造器会产生不同的完整请求hash；测试明确断言这一变化，并核对除 `state.phaseReview`外的原goal、acceptance、候选value、上下文、问题和边界全部不变。重放是**当前未修改数值校验器的离线兼容诊断**，不是原v4线缆请求的再次执行，更不能证明Jev收到新v5提示会返回相同分布。原v4请求与上述hash仍独立保留。
