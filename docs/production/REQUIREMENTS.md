# 自动化软件生产需求输入

等待用户完整需求描述后再启动实施。用户可以直接用自然语言讲目标和场景，不必填写格式化表格；以下项目用于随后归纳范围，只询问影响实施或授权的关键缺项。

## 需要从需求中确认

1. 希望用户完成的核心事情、使用者和完整操作流程，哪些结果算成功。
2. 首个 Demo 是生成新应用、修改既有仓库还是修复 Bug；一个具体例子及不希望系统做的事。
3. 目标仓库或模板、允许修改的路径、技术栈、依赖与运行环境。
4. 单文件 HTML 是否足够，还是明确需要 Node、后端、多文件、数据库或部署。
5. 用户输入、工具调用、产物与验收的边界，正常案例和应拒绝/失败的反例。
6. 四角色的职责与可选模型，是否要求跨厂商，以及 Key 如何在本分支页面配置。
7. 单次和整批成本上限、币种、时间与 Token 预算；最大返修不超过两次。
8. 容器或等效沙箱的可用环境；是否允许另行安装或启用系统服务。
9. 需求歧义、权限不足、高风险动作时允许何种人类参与；哪些动作仍应停止询问。
10. 最终交付需要本地预览、源码、patch、报告或分支；公开部署仍需独立授权。

## 不替用户推定

不将两个历史零食调查题目当成自动化生产首个需求；不将原项目 Key 迁入新分支；不因本 prompt 允许分支推送就自动建 PR、合并 main 或更新线上服务。

在确认目标后，先生成范围、任务、权限和验收摘要，再进入用户已授权范围内的最小切片。这里不是预先承诺任意代码仓库、无限工具权限或通用 L5。
