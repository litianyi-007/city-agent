## 本批改动

- 新建自定义需求清空原Mock来源/编号/验收；首次编辑已登记Mock脱离固定案例，不自动变为真实业务需求。所有输入/配置/预算编辑同步撤销旧授权；无自动付费。
- 摄像头可选结构化映射约束由用户明确填写，不用题目关键词推断。测试角色必须冻结指定映射的真实DOM文本；“可见标签”或平台映射自洽不能替代业务要求。
- 原测试角色生成后、Jev/Verifier前运行语义预检，拒绝未绑定占位符、计数变更矛盾、错误旋转、不可操作摄像头控件和缺失映射断言；保留原始拒绝输出。重生成与Gate返修共用最多两次，不手改产物。
- Verifier目标理由300/400字符，硬门限仍1000/1500、全候选ID、序数最低3分和最高分选择，不截断或修复非法理由。验证责任契约区分宿主schema、角色CSS、强制行为Gate、工程回归与实机验收，不把职责当作通过证据。
- Jev request-layout-v2在共享state完整保存rubric，question引用当前维度；固定资产事实使用完整清单hash/数量/版本，全部pins保留于控制面与manifest。需求、候选、拒绝原文与Gate均不裁剪，上下文硬限不提高。
- Camera mandatory Gate v2把实际Canvas与背景绘制基线比较，另外用同源无雪诊断验证主体不是完全画布外。冻结CSS和原场景不改；运行时hash绑定Gate源文件。此门限仍不证明每个对象/星都可见、真实视觉识别或实体设备体验。
