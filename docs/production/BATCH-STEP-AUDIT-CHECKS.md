## 对抗审查与修订

1. 免费初轮发现扩展固定协议和冗长默认tester指令使正常六个合成Key的碰撞检查超工作上限。新审计协议单独扫描，未使用的默认tester保持v2字节；实际分组生成和PM/完整评审仍使用完整v3指令，每个固定包分别核验。不抬100000工作界限、不删必需指令或绕过秘密检查。
2. P2：三个覆盖缺口用例只换名称、实际夹具相同。修为不同真实plan/steps并先断言“缺独立已有记录setup／缺逐负例业务结果／PM漏原要求”各自不足，然后显式注入弃权。只证明控制面尊重拒绝，不证明真实模型发现这些缺陷。
3. P2：接受判断保存与accepted事件之后、冻结前缺最后源重算。补最后assertSources/guard及两处保存×删除/重打audit hash四例；保留实际Oracle accept，host整体failed、0返修、无freeze/研发/Gate。
4. P2：冻结事件保存先于防漂移基线捕获，故障回调可能同时改audit与frozen hash而被采纳。改为先捕获基线、再保存事件、立即assertFrozen；新增双重重hash例阻断研发/Gate/交付。保留发生过的冻结尝试与失败，不伪造未启动。
