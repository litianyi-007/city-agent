# Verifier 18池独立挑战集：免费准备 v1

2026-10-07。本批完成评估计划 VE-01 的人工挑战集准备：12个离线HTML池、6个声明式场景池，每池两候选。36/36结构合法；实际请求拒绝Chromium逐候选执行，16个通过、20个预设业务负例失败，36个标签全部一致。另有不计分的C17有效正控。零模型请求；这不是18个真实业务需求、36次自主交付或任何模型选优/省费成绩。

独立原始记录见 [VERIFIER-PREP-01](experiments/VERIFIER-PREP-01/RESULT.md)。源码 `7755b4ddf68fec211783717d256430642d89713e`，干净工作区，实际准备116.390秒。评审是另一名外层开发Agent只读审查，不是双人工标注。此前三DEV池继续独立保存，不计入18池或未来未见任务。

8个混合池首位4好/4坏、6个双坏、4个双好。此分布是人为设计的挑战，不是自然需求成功率。当前使用准备源码顺序；正式策略交错顺序、固定种子随机化、模型及预算尚未冻结。

同池两候选共享中立DOM与完全相同业务checks；不用模型自述，实际fill/click/精确文本/值/数量判断。所有坏HTML页面首先真实加载且JavaScript健康，失败均为明确业务断言；超时、网络、语法或环境故障不能用于确认坏标签。H10准备中发现缺失中间数量断言会导致点击已误删节点超时，已在收费/冻结前加强Oracle并重验；没有修改候选去伪造通过。

场景先走原严格schema和mandatory Gate，再对照业务映射/数量/标题。generic Gate证明配置自洽，不能识别反向业务映射或缺少指定primitive：C13/C14/C17正是这类反例。C17在构造前明确左右布局，原Canvas相对真实背景按半画布采像素；使用原scene一次粒子生成、按object.count分片验证投影/glow互不串扰。每primitive的独立无雪派生另列，不冒充原scene粒子坐标。有效正控验证两侧和两primitive都能通过，仍不加入36候选分母。所有相机默认关闭，未请求媒体权限。

## 盲评与容量准备

labels、defect、分层与Oracle结果只在控制面。候选使用opaque ID，不写正确版/错误版注释。白名单review包含完整候选、原需求、冻结业务checks/场景要求与合法平台事实；无先前策略意见、答案、执行结果或标签。

每池记录候选value JSON、HTML UTF-8/scene JSON、checks/要求、逻辑prompt/Jev请求、rubric及配置hash。value JSON hash不等于HTML原文hash，文件原始字节hash也不等于去空白JSON重序列化hash。

## 复现

在本研发线分支、Node22.19+、依赖与Chromium准备完成后，从名为`city-agent-autonomous-production`的独立仓库/worktree目录执行：

```sh
node --import tsx scripts/prepare-production-verifier-corpus.ts
```

脚本仅免费工程准备，不需要Key，不实例化生产Store、不读取凭据或调用Provider。固定校验本分支及真实输出目录，创建独立随机`output/production-verifier-preparation-*`，不覆盖旧记录。31个声明源码/lock依赖、HEAD/分支在每次前后与结尾校验，candidate/checks不得改变。每个候选先wx写intent，再写实际Oracle与terminal；取消/throw的已启动候选不算not-started。它不是持久化恢复或正式收费实验runner。

这些磁盘hash不证明缓存模块字节、完整node_modules或操作系统沙箱；受限Chromium也没有容器CPU/磁盘硬配额。候选只在现有浏览器控制环境执行，不执行生成的宿主Node/shell。仓库没有独立LICENSE文件；manifest的“repository license applies”不是新增SPDX许可或第三方授权声明，本批候选为外层自行编写、无第三方候选源码。
