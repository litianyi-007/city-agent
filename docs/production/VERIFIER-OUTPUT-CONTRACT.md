# Verifier 输出契约、边界证据与失败反馈

2026-10-08。此增量修复 [VERIFIER-REAL-01](experiments/VERIFIER-REAL-01/RESULT.md) 暴露的输出与审查问题，适用于实际六角色生产链路和独立 A/B/C 评测。这里是平台工程实现，不是新的真实模型成功实验。原失败账本、控制授权、视频、申报稿和 GitHub Pages 不改写；此前一次真实对照授权已消费。

## 版本与不变的门禁

- `verifier-phase-ordinal-v5`：逐条依据当前阶段检查原始验收，包含适用的等于阈值、相邻值、空值、最小/最大、零/负值、舍入和状态转换；不要求早期角色拿出尚未执行的后期产物。
- `verifier-compact-output-v2`：候选理由目标120字符、总理由目标160字符。理由只概述关键证据或缺陷，不复制代码、不输出内部思维过程。目标长度不是截断规则，宿主原1000/1500字符上限不变。
- `verifier-decision-diagnostic-v1`：有界、固定字段的输出错误诊断。
- `verifier-study-strategy-v2` / `verifier-study-source-v3`：评测策略与47项执行源码 hash 绑定新模块；独立生产启动身份仍自动覆盖源码目录。

模型只能返回一个 JSON 对象。Prompt 中的合法例子由 `JSON.stringify` 构造；明确要求双引号、反斜杠和控制字符正确转义，理由为标量字符串，不混用伪枚举、JS表达式或 Markdown。宿主仍拒绝非法输出，不做本地 JSON 修补、提取散落 JSON、截断、强制接受、模板回退或递归复核 Verifier。

接受条件仍为：当前全部候选恰好各评分一次，整数0–5，选择当前候选且至少3分，并达到当前最高分；最高分并列可以选择其中一个。弃权必须选择 `null` 并为全部候选评分。结构合法或相对最强不代表业务合格；存在确定的必需行为矛盾应低于3分，全坏或证据不足池应弃权。通过模型评审后仍须通过研发前冻结的独立行为 Gate。

新文本入口额外设 32,000 UTF8 字节上限，并拒绝同一对象的重复 JSON 键，包括 Unicode 转义后同名的键；不改变其他角色的 `parseJson` 历史行为。这两项收紧属于新版本，不能倒推旧实验使用了同样规则。为了兼容既有输入，宿主仍接受原来的完整 JSON 围栏语法；新 Prompt 要求模型不返回围栏，不承诺供应商必然遵守。原 Jev 单问题/总请求 32,000/64,000 字节与评测逻辑 LLM Prompt 60,000 字节门限不变。

## 可解释的失败分类

| 类别 | 固定原因 | 安全诊断内容 |
| --- | --- | --- |
| `response-bound` | 非字符串或超过32000 UTF8字节 | 长度与上限；超长文本不再计算内容hash |
| `json-syntax` | 非法 JSON 或重复对象键 | 完整输入hash、UTF16长度、body偏移与错误位置；引擎没有位置时为null |
| `zod-structure` | 严格字段/类型/范围/数量违约 | 最多12个固定路径和代码、总问题数；不公开任意属性名 |
| `candidate-ids` | 当前候选评分缺失、重复或外来 | 仅候选/评分/缺失/重复/外来数量，不回显响应中的ID |
| `selected-id` | 弃权仍选候选、接受却为null或未评分ID | 固定代码和 `selectedCandidateId` 路径 |
| `minimum-score` | 选中分数低于3 | 受schema约束的选中分数与最低3分 |
| `highest-score` | 未选最高分 | 受schema约束的选中分数与最高分 |

不导出 V8/Zod 原错误文字、未知属性路径、候选理由、来源片段或原始 `cause`。语法扫描在 JSON 解析成功后使用迭代栈，避免攻击者控制的深度导致递归溢出。原始模型输出仍由已有受控传输/Store脱敏后留证，诊断不替代原件。

生产链路把相同诊断保存到角色调用、评审记录和固定错误事件；协议错误直接终止，不消耗候选再生成预算、不启动第二次 Verifier。评测把诊断写入 `decision-result`，仍按既有规则停止整轮。未知用量、超时和预算策略不变；旧实验没有这些新增字段，不补写。

诊断版本进入 `validationContract`，继而绑定调用配置、评审标准和冻结验收的 hash。固定诊断路径、代码、版本及其至少16字符子串加入凭据保留值，避免把这些协议字面量填成 Key 后由脱敏破坏结构。这只防止可列举的静态冲突，不证明任意秘密变换安全；动态hash若与旧凭据碰撞仍优先保护秘密，不承诺所有诊断字段永远不会被脱敏。

## 本批免费反例，不冒充模型能力

1. 原H04响应SHA256 `a3db2e3e85211a67000dee4b2a3d96e1968b4ac6ec9a871a61c4aa27c437b170`，同样在UTF16位置238失败；只有一次注入LLM回调，无修复结果、无第二次请求。原归档终态仍failed。
2. 生产链路分别注入语法、结构、候选ID、选中ID和低分错误：诊断持久化、无再生成、无行为Gate、无交付附件。
3. 原H02 `total>100` 候选在免费实际Chromium中执行原“含100元九折”冻结检查：即使注入的Verifier始终打5分，实际Gate仍失败且不能交付。此为外层工程测试，不是补跑原收费实验的Oracle，也不填入其质量分子。
4. 合法转义、完整评分和合法弃权正例通过；重复键、转义同名键、截断、非法转义、未知字段、低分、非最高分与外来ID负例拒绝。
5. [Jev数值兼容回放](VERIFIER-JEV-COMPATIBILITY.md)保留原3响应、2次arithmetic-drift和1次uncertain，不扩大±0.005假设。当前v5阶段rubric与原v4请求分开，不宣称新提示会产生相同真实响应。

完整免费验收和审查见 [本批验证记录](BATCH-VERIFIER-PROTOCOL-CHECKS.md)。新版增加了边界提示，也增加部分输入内容；输出目标变短不等于总Token、费用或误判下降。只有新配置下的完整真实对照和行为结果才能判断质量/性价比。
