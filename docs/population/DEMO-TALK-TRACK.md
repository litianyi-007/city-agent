# 三分钟讲清 City Agent 的人口可信度

## 0:00—0:40：先说明双重交付

“City Agent用产品、研究员、研发、测试四个角色，从任务开发可运行页面。它还有一条独立的人口证据链：事实有原表，推断有公式，模拟有规则和版本。工程验收通过与商业研究有效，分别报告。”

在工作台指向两个现成例子：小学生零食店、宠物零食网点。使用“流程演示”，说明无需Key、无模型调用；真实模型入口才经DeepSeek Harness调用实际模型。不能把mock成功宣传为真实模型成功率。

## 0:40—1:40：从人口数字回到原表

打开“城市与样本”：2020七普503,859人，西兴143,318、长河168,276、浦沿192,265。与2025年末55.9万人并列，强调普查时点与年末抽样推算不同，最新区总量不等于最新街道结构。

选择“西兴 / 0–4岁 / 男”的模型单元：页面显示逻辑人口、独立性公式、固定边际可行界。追到total和女性原始格，男性是明确减法派生；再点击下载原件，打开年鉴PDF117页/印刷109页的性别边际，以及PDF120页/印刷112页的年龄边际。来源页登记发布日、采集日与SHA-256。

“这里没有公开联合表，我们没有把推断改名事实。哈希只能证明文件没有变，不证明普查绝对无误差。”

## 1:40—2:30：用问题暴露边界

启动“小学生零食店”：角色完成条件研究页面，但decisionStatus保持needs-data。5–14岁不是小学生，15+规则受访样本不能套用；还缺当前学校/在校生、实际出入口与候选店、家长选择和成本。

启动“宠物零食网点”：人口不是养宠率，自有订单也不是全区偏好。先分清自提/履约/获客以及零食/主粮，补匿名客户分布、猫狗类别、规格、成交价、复购与成本。猫向/狗向/混合都是待证伪实验，不是已经研究出的主营方向。

在页面切换条件假设、选择要补采的数据。操作只改变补采计划，不会把空白证据“勾成已完成”。交付的是可执行的研究下一步，而非未经验证的开店建议。

## 2:30—3:00：说明可复制性

下载新区域模板，上传预检：空模板应被阻止。将新区域原件存档、逐格录入、核验完整边际，再使用同一个CLI编译。方法复用，事实不能复用。界面未实现任意城市自动采集/自动发布，也没有把学校、家庭、养宠信息凭空补齐。

## 常见追问

| 问题 | 可诚实给出的回答 |
| --- | --- |
| 为什么不用最新人口结构？ | 本次核验取得2025区级总量和性别，没有相同粒度的最新街道年龄联合表；因此新旧分层，不伪装同年。 |
| 50万人就是50万个Agent？ | 不是。24个逻辑人口单元、按需抽样；开发角色与居民数据分离。 |
| 总量准确是否证明模拟偏好准确？ | 不证明。偏好要业务证据、真实补采和外部验证，增加LLM回答数量也不自动提高真实性。 |
| 为何结果没有直接推荐浦沿或猫粮？ | 人口最多不能决定客流、猫狗结构或利润；给无依据结论会降低系统价值。现在明确给补采与条件实验。 |
| 我能换区域吗？ | 可用模板和CLI完成录入/校验/编译，应用内当前固定滨江；下一阶段做数据包发布与城市切换。 |
| 什么才是成功？ | 能回查每条事实，能复算每个推断，能看到哪些决策还不能做，并且页面真实通过独立测试。 |
