## 1. 当前状态

仓库只有评审文档，没有应用代码。Phase-1 范围已写在产品文档里，作为评审基线：评审可以改它；没写进去的功能默认不做。

## 2. 评审前

| 项 | 状态 |
| --- | --- |
| 产品、架构、路线文档进入评审用的 PR | 由本变更完成 |
| 冻结 Phase-1 范围（写入产品文档第 4 节，供评审打） | 已写入，尚未经过外部签字 |
| 人口统计问题清单（产品文档 D1–D12） | 已写入，尚未召开评审 |

下一项行动是召开**限时**人口统计 / 统计学评审，不把评审人加入创始讨论群。评审输出按 D1–D12 答复，并指出要改的契约编号。交互、人类学、游戏评审不在这一场里做（产品文档第 6.1 节）。

在该书面答复合入文档之前：不冻结物理 schema，不写 `ExternalDataAdapter`，不开始 L5 执行器集成。

## 3. 评审之后的顺序

一步完成并在文档或运行记录里留证据，再开始下一步。

| 序 | 任务 | 完成时看什么 |
| --- | --- | --- |
| 1 | 把评审答复写回 `PRODUCT.md` / `ARCHITECTURE.md`。收紧的口径、阈值、分层变量成为契约正文，不留在聊天记录里。 | D1–D12 每条都有「采纳 / 维持原默认」及对应契约 |
| 2 | 按 C1–C11 落 schema（SQLite 即可）。包含来源登记、`FactRecord`、`Persona` 属性级 provenance、`Edge`、`Cohort`、`RunManifest`。 | 架构文档第 7 节的七条实现约束有地方可放 |
| 3 | Spike：`ExternalDataAdapter` 只接**一个**滨江公开来源，覆盖三街道中至少年龄 × 性别，并带 citation 与必填口径。 | 缺 citation 的格子进不了事实表；适配器不做下推 |
| 4 | `PopulationBuilder` v0 + 结构自证的第一版。对照该来源的边际，输出距离；阈值只用参数。 | 抽查任意属性，`infer` / `generated` 不会呈现为 `fact` |
| 5 | `RelationEngine` v0：`family` 与 `colleague`，以及整臂关闭。 | 同一人群框可以跑「规则开」和 `no_social_rules`，边际不变 |
| 6 | 调研路径走通：`Sampler` → `BatchAnswerer` → `Analyzer` → `EvalHarness`。演示夹具用「AI 生活服务会员」，除非第 1 步改了夹具。含三类自证入口、两臂双基线，以及至少一臂朴素对照（演示默认 `direct_llm`）。 | 一次主运行写出分析；跑过的每一臂都有 `RunManifest` |
| 7 | `CohortPack`：居民包（服务抽样）与研发包（固定小角色表 + 更密的协作边）。 | 研发包成员能作为受访者被抽到；导出的上下文不含工具权限 |
| 8 | L5 叉的 spike（与调研叉并行的那条产品线，排期上接在研发包之后）。用一份假规格（小型 Web 应用 + 验收测试），走 `SpecStore` → 选定的一条 `CodeExec` → `QualityGate`。上下文使用第 7 步研发包的只读快照。 | 中途无人工；通过条件与 C11 一致（验收退出码为 0，且启动命令能跑起应用）；失败运行不能手改判通过 |
| 9 | 演示脚本：按成功标准走一遍调研主路径，并填满成本字段（Token、墙钟、估算成本、价格表版本）。L5 spike 的 Gate 证据附在同一次演示说明里。 | 第三方只凭 `RunManifest` 与脚本能复述设计并重跑 |
| 10 | 第二次限时人口统计评审：看结构自证和口径落地，不在这场扩范围。 | 书面结论再次写回文档 |

第 8 步使用假规格，是为了验证门禁，不代替将来的真实产品规格。假规格不进入调研演示叙事。

## 4. 非目标

实现队列不包含：

- 多源数据融合、POI 营销场景、京沪穗扩展。
- 约 30 万居民的逐人 Agent 或逐人富属性物化。
- 社会 tick、MoA 运行时、wikiskill、长期记忆、Crew 式作答。
- deepseek-harness 调研运行时；同时维护 OpenHands 与 SWE-agent 两套 L5 后端。
- 上链、图数据库、记忆服务。
- 游戏数字资产、MMO-AI、`extension_point` 的任何运行时代码。
- 诱导问法检测、自然语言创建调研、真人问卷对照、广告实验。
- 生产部署意义上的 L5「上线」。
- 在创始群里常驻外部专家。

## 5. 开放问题

建议默认用于「评审沉默时仍能往下做」。评审答复与建议默认冲突时，以答复为准，并修改文档。

| ID | 问题 | 建议默认 |
| --- | --- | --- |
| O1 | 第一个 `source_id` 用哪份公开资料？ | 只选一张能支撑三街道年龄 × 性别的公开表（普查分街道表或等价年鉴表）。不在 spike 里融合第二来源。 |
| O2 | 主口径是常住还是户籍？ | 不猜测。`population_basis` 保持无默认值。spike 的那张表用它自己的口径名，并在演示中念出来。 |
| O3 | 结构距离的阈值？ | 只计算并展示距离。阈值保持配置项，默认不设为 Gate 失败条件，直到 D6 给出数字。 |
| O4 | 逻辑人口 N 与抽样 n？ | N 来自所选公开合计，规划上限参考约 30 万，不把「做满 30 万行人格」当目标。n 与分层等待 D7；未答复前不开始为演示夸大样本量。 |
| O5 | L5 执行器选 OpenHands SDK 还是 SWE-agent/mini？ | spike 先接 OpenHands SDK。接入成本明显高于换 SWE-agent/mini 时，只换这一条并写回 ADR-004，不两套并存。 |
| O6 | 演示问卷是否用命题里的 15 题？ | 用。题面作为夹具版本化进 `instrument` 哈希。换题必须改产品文档里的夹具说明。 |
| O7 | 批量作答与追问是否分模型？ | 允许分模型。模型名不在路线图锁定，第一次真实调用记入 `RunManifest`。 |
| O8 | `family` 边如何生成？ | 户规模边际（若有公开数）加简单户内角色模板。无联合公开表时 provenance 用 `infer` 或 `generated`，不用 `fact`。 |
| O9 | 估算成本的单价谁维护？ | 仓库内一份价格表，`RunManifest.price_table_version` 指向它。没有单价时成本字段为未知，禁止填 0。 |
| O10 | 研发包有哪些角色？ | 固定短列表即可，例如产品、工程、设计、研究。列表写在包规格里。角色不负责执行 `CodeExec`。此问题不阻塞第 3–6 步。 |
| O11 | 稳定性重复次数 K？ | 在 D10 答复前，演示采用命题案例中的 5 次作为 `consistency_stability` 参数，不把 5 写死在代码常量里。 |
| O12 | 双基线的种子是否与主运行相同？ | 相同抽样种子与相同问卷哈希；`no_external_data` 使用单独的人群框 id，并在记录里标明。避免用「另一批完全不同的随机人」冒充对照。 |

## 6. 完成定义

Phase-1 实现结束，当且仅当：

- 调研四项成功标准都有一次可演示的证据（端到端、三类自证、双基线加朴素对照、成本与 `RunManifest`）。
- L5 假规格或当时已替换的真实小型应用规格，在无中途人工的前提下通过 `QualityGate`，且研发包仅为只读上下文。
- 第 4 节的非目标仍然没有代码路径。

文档与契约在整个实现过程中保持可评审：行为变化先改本文三份文档，再改代码。
