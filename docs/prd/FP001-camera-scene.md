# FP001：受控手势场景生产能力

功能分支：`feature/autonomous-production`（复用已隔离的生产研发线，不新建或切换他方分支）。
创建日期：2026-10-07。状态：用户已确认摄像头能力扩展；本文件冻结第一轮实验的工程范围。版本：v1.0。

## 概述

用户原话：“开发一个梦幻的圣诞树，能通过摄像头获取手势，来控制圣诞树”。用户随后确认三种手势和受控摄像头能力，并已在生产页面设置六角色 Key。

这是用户提出的真实测试需求，不是已上线业务工单，也不能补足“三个真实业务需求”。目标是通过本地前端输入，观察平台内部六角色和 Verifier/Jev 的交付质量；外层开发者先建设通用能力，不手改内部 Agent 本轮生成产物。

前置能力原为离线单 HTML + 禁止请求的 Chromium Gate + 静态截图，不支持摄像头。不能悄悄删除摄像头要求，不能恢复未经隔离的任意模型脚本 iframe。

## 功能范围

- 新增显式、版本化 `camera-scene-v1`，旧 `offline-single-html` 与实验保持不变。
- 平台提供可信固定摄像头、本地识别、粒子几何渲染和生命周期运行时；Agent 生成严格校验的 JSON 场景、颜色、几何和手势映射，不生成运行时可执行脚本。
- 通用几何为 cone / sphere / ring / star；不通过“圣诞树”关键词分支返回固定成果。
- 张掌散开，握拳聚合，掌心横向位置旋转；支持明确标记的按钮与键盘回退。
- 运行时资产固定版本、官方来源、SHA256 和许可证；运行时只读本地准备资产，不使用 CDN。
- 保留角色原始输出、候选接受/弃权、冻结验收、返修、成本和失败证据。

不做：任意仓库/Node/shell 执行、模型脚本获得视频帧、自动批准实体摄像头权限、手机/所有浏览器兼容承诺、用关键点夹具证明图像识别可靠、用预测代替实测。

## 用户故事与验收

### Story 1：本地需求输入与 Agent 交付（P1）

1. Given 六角色 Key 和 USD 单价已配置，When 在生产前端选择该能力并输入原始需求/验收，Then 请求经真实 Harness 六角色、候选 Verifier 与不可放宽的冻结 Gate 执行，保留 Run ID、Prompt 和费用。
2. Given 候选契约非法、弃权、超时或返修超过两次，When 运行结束，Then 明确失败，保留全部尝试，禁止固定模板回退。

### Story 2：受控场景行为（P1）

1. Given 合法模型场景 JSON，When 可信渲染器加载，Then 非空粒子图形显示，散开/聚合改变实际渲染几何，左右旋转改变投影；不是静态“通过”文案。
2. Given 模型数据包含 URL、脚本、超限粒子、非法颜色或未知字段，When 校验，Then 拒绝，禁止执行或任意合并。

### Story 3：明确许可的摄像头（P1）

1. Given 页面初次打开，When 用户未点击启动，Then 不请求媒体权限、无音频或推理；点击启动后才请求视频，并在本机固定模型中推理。
2. Given 拒绝、无设备、设备占用或模型加载失败，When 初始化，Then 显示真实状态并允许按钮回退，不标记摄像头通过。
3. Given 启动中立即停止、迟到的媒体流、重复启停或关闭页面，When 清理，Then 所有 tracks 停止，video.srcObject 清空，推理/worker 结束，不保存帧。

### Story 4：验证口径（P1）

1. Given 合成关键点 / 假摄像头浏览器通过，When 展示 Gate，Then 标记“受控场景行为 / 合成输入”，图像模型、真实设备和全需求验收仍未验证。
2. Given 用户允许实体摄像头试用，When 实机确认，Then 单独记录设备、权限、光照、三种手势、无手、停止与延迟；不得把外层人工验收称无人干预。

## 功能和非功能要求

- FR-001：角色、模型、Key、候选评审和预算沿用现有通用契约；不自动迁移其他工作区凭据。
- FR-002：在研发前冻结需求、测试与能力版本/hash；返修不能修改 Gate。
- FR-003：最多两次返修，运行超时/预算/取消后保留终态；不自动重放收费请求。
- FR-004：生成场景与平台运行时分别记录来源/hash；Jev 范围评分必须使用新能力定义，不把摄像头需求按旧范围拒绝或冒称已实机验证。
- NFR-001：首批每任务估算上限 5 USD、总计 15 USD；unknown 不记为零。单价来源记录，估算不是账单。
- NFR-002：桌面 Chromium 优先；手势推理独立 worker，最多一帧在途，节流。实际 FPS/延迟未测量时不宣称达标。
- NFR-003：摄像头原始帧不上传/不进入 Prompt、日志、导出；默认 audio:false；模型 Key 仅控制面持有。资源上限不能被称为 OS 安全沙箱。
- NFR-004：控制可键盘访问、按钮至少44px、明显焦点、375/768/1024/1440无横向溢出，尊重 reduced-motion。

## 实现阶段与完成条件

- T001：固定严格场景 schema、版本化能力、角色提示和 Jev rubric。完成条件：负面输入测试通过，旧契约回归通过。
- T002：可信几何渲染和手势状态机。完成条件：实际 Canvas/几何交互、去抖/无手、恶意文本测试通过。
- T003：固定本地模型资产。完成条件：来源、版本、SHA、许可证与准备脚本可复现，缺失或变更失败关闭。
- T004：摄像头生命周期。完成条件：拒绝、初始化失败、迟到媒体流、停止、重复启动测试通过；不是实体设备证据。
- T005：前端能力选择、交付入口与局限说明。完成条件：原生产/虚拟社会回归，无任意模型脚本预览。
- T006：冻结首轮实验后，通过本地页面输入需求启动真实内部模型。完成条件：完整记录；失败亦为有效实验，不修改产物或门限。
- T007：用户实机确认。完成条件：实体设备验收另列；等待用户操作不虚构完成。

## 风险与未决项

无授权真实手势视频样本时，模型识别准确率不能测量；无实机许可时，不证明实体摄像头效果。场景配置自主生成不是全部源码自主生成；可信运行时是平台先行工程。官方模型可能含统计能力，须结合固定源、CSP、请求测试审查，不仅依赖厂商隐私声明。

不存在正式比赛 L4 标准；只能对上述有界契约自评。第一轮成功也不证明泛化或稳定通用 L5。
