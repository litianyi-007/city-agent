## 1. 愿景

建设一个虚拟社会平台**底座**，使多条产品共用同一套人群、关系与人群包。

- **近期：** 两条竞赛轨道共用这一底座。
- **远期：** 底座可以承接 MMO-AI 游戏基底。这是愿景，不是 Phase-1 的功能、排期或验收项。

Phase-1 只证明底座能同时喂给「可调研的人群」和「有界的自主研发」。不证明完整虚拟社会、长期运转的多 Agent 世界，或游戏。

## 2. 近期两条轨道

### 2.1 调研轨 — 滨江 AI 镜像社会问卷

目标区域：杭州市滨江区的西兴、长河、浦沿。命题允许换到其他城市的公司办公区；Phase-1 不换。

业务用途与命题一致：正式真人调研之前的问卷预演、假设筛选和方案比较。仿真结果供业务参考。产品主张到此为止。

数据路径：

```text
公开数据 → 人群（带来源标注）→ 按规则抽样 → 代表性人设批量作答 → 分析与自证
```

命题对这条轨道的硬边界（Phase-1 遵守）：

- 先有数据支撑的总体结构，再抽样。禁止先编一批人再反推结构。
- 信息分三类，下游必须沿用这三类，禁止混称：
  - **公开事实** → provenance = `fact`
  - **统计推断** → provenance = `infer`
  - **模型生成** → provenance = `generated`（性格、兴趣、具体态度等）
- `infer` 与 `generated` 不得被说成真实社会事实。
- 逻辑人口是总体框。命题建议的规划参考值约 30 万。不为每一名居民创建或常驻一个大模型 Agent。
- 效果与 Token 成本同时被考察。手段包括分层抽样、统计加权、代表性人设、批量推理、大小模型协同、缓存。具体模型名字不在本文锁定。
- 自证至少三类：结构、角色一致性与稳定性、变量敏感性（价格、权益或其他业务变量的方向是否说得通）。
- 命题不提供统一的真人问卷基准。Phase-1 也不把「对齐某次真人结果」当作验收。

命题建议的评测权重只用于调研轨演示时的取舍：公共数据与人群结构 25%，角色自洽与仿真合理性 25%，问卷流程与分析价值 20%，性能与成本 15%，可解释、可追溯、可复现 15%。公司两条轨道的成功标准以第 5 节为准。

### 2.2 L5 轨 — 有界能力的自主研发

定义：给定书面规格和验收测试，系统在**一次运行**内独立完成该能力类的开发，运行中途没有人工介入。人可以在运行前写规格，在运行后看结果。

第一刀：小型互联网应用，路径为 `规格 → 可运行 → QualityGate`。

同一时期不做游戏数字资产、美术资源管线或游戏内经济。那些属于愿景或其他阶段。

L5 的执行器是代码执行链路（`CodeExec`），不是虚拟人群。研发团队人群包只提供只读上下文（第 3 节 H4）。

## 3. Phase-1 假设

这些是待检验的主张。第 5 节的成功标准要求对照**做出来并可解释**，不要求在评审前承诺胜出幅度。

| ID | 主张 |
| --- | --- |
| H1 | 用公共数据支撑的滨江人群、可引用的外部数据，以及可关闭的轻量社会规则，可以低成本地做出连贯、可追溯的问卷仿真；在受控对照下优于纯虚构人设。 |
| H2 | 可核验的外部数据，加上拟人社会规则，相对两个基线提高外部效度：`no_external_data`（无外部数据）、`no_social_rules`（无社会规则）。 |
| H3 | 给定书面规格和验收测试，自主执行能产出一个通过 QualityGate 的小型 Web 应用，且该次运行中途无人工介入。 |
| H4 | 研发团队是一种特殊人群包：一组角色，加上比普通居民更密的协作边。它同时是调研受访者，以及 L5 的编排上下文。它不是 L5 执行器，不持有工具，不改代码。 |

轻量社会规则在 Phase-1 的操作定义：`RelationEngine` v0 的 `family` 与 `colleague` 边。规则打开时，作答可以读取这些边；基线运行必须能把规则关掉。

## 4. 范围

### 4.1 纳入

**共享底座**（两条轨道都依赖；第三条产品以后也从这里接，而不是改叉的内部）：

| 模块 | Phase-1 职责 |
| --- | --- |
| `ExternalDataAdapter` | 把已登记的公开数据切片编译成带引用的 `FactRecord`。不做推断。 |
| `PopulationBuilder` | 生成 `Persona`，每个属性带 provenance：`fact` \| `infer` \| `generated`。 |
| `RelationEngine` | 产出 `Edge`（类型、权重、`rule_id`）。v0 类型为 `family`、`colleague`。基线可关闭规则。 |
| `CohortPack` | 产出 `Cohort`：成员、角色、子图。包含普通居民包和研发包。 |

**Fork A — 调研：**

| 模块 | Phase-1 职责 |
| --- | --- |
| `Sampler` | 按街道、年龄等设计从总体框抽样，并保留权重与种子。 |
| `BatchAnswerer` | 用代表性人设做批量、条件化作答。人设按问卷上下文作答。不是常驻 Agent。 |
| `Analyzer` | 样本结构、总体结果、交叉分析、典型回答及其画像依据、业务结论与风险提示。 |
| `EvalHarness` | 三类自证、双基线、成本，并且**每次运行**写 `RunManifest`。 |

**Fork B — L5：**

| 模块 | Phase-1 职责 |
| --- | --- |
| `SpecStore` | 保存冻结的书面规格与验收测试。 |
| `CodeExec` | 在有限工具链内执行该次自主开发。 |
| `QualityGate` | 对产物跑验收。通过/失败必须有证据。 |

`CohortPack` 对 L5 只读。研发包可以出现在规格上下文里（角色、协作关系），不能成为调用工具的 Agent。

**愿景接缝：** 文档中的 `extension_point`。没有 Phase-1 行为。

### 4.2 不做（Phase-1 非目标）

下列各项即使命题简报列为加分、或研究材料里出现过，也不进入 Phase-1 交付：

- 完整 MoA 社会运行时、部门集体、dream / growth（wikiskill 一类机制）。
- 常驻多 Agent、社会 tick、为逻辑人口中的每个人维持一个 Agent。
- 以 deepseek-harness 作为调研运行时。
- Crew 式多 Agent 来实现 `BatchAnswerer`。
- Mem0、Letta、Zep 等记忆产品；虚拟居民长期记忆。
- Chainlink 或任何上链实现。可核验外部数据只做到适配器 + 来源登记。
- MMO-AI 功能；L5 的游戏数字资产切片。
- 把专家长期留在创始讨论群。外部意见用限时评审，结论写回文档。
- 完整商业问卷系统、自然语言创建调研、广告投放地点仿真、诱导性问法的自动识别。
- 小规模真人问卷对照（命题鼓励、不强制；Phase-1 不作为交付）。
- 社区尺度的社会网络、群体舆论动力学。关系停在 v0 的家庭与同事。

### 4.3 收窄默认

同一句话可以做宽做窄时，Phase-1 取窄的一边：

| 议题 | Phase-1 采用的窄解释 |
| --- | --- |
| 地理 | 只做滨江西兴、长河、浦沿。 |
| 总体规模 | 约 30 万是逻辑人口的规划参考，不是「要仿真 30 万个 Agent」。未抽中的人不物化成富属性行。 |
| 第一个数据源 | 只接一个能支撑街道 × 年龄 × 性别的公开来源，再谈多源融合。具体来源见路线图开放问题。 |
| 演示问卷 | 用命题参考案例「AI 生活服务会员」作为演示夹具，不把它写成平台唯一题型。 |

## 5. 成功标准

### 5.1 调研轨

四项都要有，缺一不算 Phase-1 完成：

1. **端到端演示：** 数据采集与处理 → 虚拟人群 → 问卷投放 → 模拟作答 → 结果分析。采集与清洗可以在演示前做好；演示时要能讲清来源、口径和时间。
2. **三类自证：**
   - `structure`：年龄、性别、教育、就业等主要结构与所引用的公开数据的对比。
   - `consistency_stability`：同一角色在相关题目上自洽；同一问卷、同一参数多次运行时，整体结论相对稳定。
   - `variable_sensitivity`：价格、权益或其他业务变量变化时，反应方向说得通，并能指回人群结构。
3. **真实性对照：** 对 H1/H2 的双基线各跑一臂并写出解释。双基线名称固定为 `no_external_data` 与 `no_social_rules`。命题还要求与「直接询问大模型」或「随机回答」至少一种简单方法对比。两臂名称是 `direct_llm` 与 `random`（朴素对照，不与双基线混名）。Phase-1 验收至少跑通其中一臂，演示默认 `direct_llm`。
4. **成本与可复现：** 每次运行有 Token、墙钟时间和估算成本，并有一份 `RunManifest`。复现标准是：第三方按记录重跑后，能核对设计、模型和**汇总结论**是否落在稳定性自证的范围内。不要求大模型正文逐字相同。

分析输出至少包括：样本结构、总体统计、交叉分析、典型虚拟居民的回答及画像依据、业务结论与风险。风险里必须标明哪些结论依赖 `infer` 或 `generated`。

### 5.2 L5 轨

一次无中途人工介入的运行：`SpecStore` 中的规格 → `CodeExec` 产出可运行的小型 Web 应用 → `QualityGate` 通过。

研发 `Cohort` 只作为只读上下文出现在该次运行中。Gate 失败则该次 L5 切片失败，不能改由人在中途补提交来算通过。

## 6. 外部评审计划

### 6.1 立场

评审是限时的、有书面输出的。评审人不进入创始讨论群作为常驻成员。输出写回产品或架构文档，并指向被约束的契约编号。

Phase-1 评审顺序：

1. **人口统计 / 统计学（现在，实现之前）。** 对象是口径表、抽样和结构自证。输出变成契约约束。
2. **交互（调研路径能演示之后）。** 业务读者能否看懂「谁在回答、依据是什么」。
3. **人类学（`RelationEngine` v0 之后）。** 家庭/同事规则是否把统计关系写成了文化事实。
4. **游戏相关评审：** Phase-1 不安排。

### 6.2 人口统计评审要交回什么

一份书面答复，逐条对应第 6.3 节。每条答复如果改变了数据含义，需要写明约束的是哪条契约（架构文档第 4 节的 C1–C8）。没有答复的条目，保持架构里的窄默认，不在实现时私下放宽。

### 6.3 人口统计 / 统计学问题清单

请评审人直接改口径，不要只评「方向是否正确」。

| ID | 问题 | 预期约束对象 |
| --- | --- | --- |
| D1 | 西兴、长河、浦沿采用哪一版行政区划边界？与后续 POI 是否必须同一版本？ | C1 `geo_scope.boundary_vintage` |
| D2 | 结构自证的主人口口径是常住、户籍，还是其他？就业地、在校人口是否允许进入 Phase-1 主表？ | C1 `population_basis` 必填；禁止缺省混口径 |
| D3 | 七人普与更新的年鉴/公报冲突时，哪一份可以标 `fact`，哪一份只能作为 `infer` 的输入？ | C1 引用；C2 provenance |
| D4 | 街道级缺失时，允许哪些下推（区级按比例、按产业、按 POI）？是否全部必须标 `infer`，且适配器禁止在编译阶段填补？ | C1 只出事实；C2 独占推断 |
| D5 | 年龄、性别、教育、就业/职业、家庭阶段中，哪些是结构自证的必对齐维度？哪些在没有公开表时允许缺失并在分析里声明？ | C2 属性清单；C8 `structure` |
| D6 | 「基本吻合」用什么量（份额差、总变差距离或其他）？Phase-1 是只报告距离，还是同时给通过阈值？阈值未给出前，实现只把阈值当作参数，不写死。 | C8 结构自证 |
| D7 | 逻辑人口 N 如何由公开合计得到？抽样 n、分层变量的最小集合（是否至少街道 × 年龄 × 性别）、是否放回、权重定义？ | C5 |
| D8 | 收入、消费能力、价格敏感度在没有街道级公开数时，是否禁止标 `fact`？ | C2 不变量 |
| D9 | 家庭户规模与人生阶段有没有可用的联合公开表？若没有，`family` 边是否必须标 `infer` 或 `generated`，并在关闭规则的基线中完全不参与作答？ | C3 |
| D10 | 重复运行的稳定性如何操作化（例如套餐排序、主要结论在 K 次中至少几次一致）？K 的默认值是否采用命题案例中的 5 次？ | C8 `consistency_stability` |
| D11 | 双基线是否公平：`no_external_data` 是否仍用同一问卷、同一作答预算？`no_social_rules` 是否保留同一人群边际、只关规则？种子政策是否要求对齐？ | C3 开关；C8 对照臂 |
| D12 | 教育、职业编码使用哪套分类？街道之间分类不一致时，谁有权合并类目，合并结果算 `fact` 还是 `infer`？ | C1–C2 |

### 6.4 后续两场评审的最少问题

交互评审（调研可演示之后）只问：

- 从一条业务结论能否走到样本、人设、provenance 和引用？
- 演示夹具是否支持一次有业务意义的比较（价格或权益）？
- 交叉分析是否覆盖街道，以及至少一个人口维度？

人类学评审（关系 v0 之后）只问：

- `family` / `colleague` 规则的依据是统计表还是模型补全？标注是否与依据一致？
- 打开规则与 `no_social_rules` 的差异，有没有被写成「已经证明了社会影响」？
- 规则有没有把某一文化脚本当成全体滨江居民的事实？

## 7. 命题简报的用法

简报用于核对调研轨用语：三街道、三类信息、三类自证、成本与执行记录、预演而非替代真人调研。

简报里的加分项（长期记忆、社区网络、多轮/A-B 产品化、真人对照、诱导识别、自然语言建任务、广告场景、UI 创意）不自动进入范围。若评审要把某一项升格为 Phase-1，必须改第 4 节并增加对应契约，否则实现不加。

地区 FAQ 允许扩展到北京、上海、广州的办公区。Phase-1 仍只做滨江三街道。

## 8. 术语

| 术语 | 含义 |
| --- | --- |
| provenance | 属性来源，取值仅 `fact`、`infer`、`generated`。 |
| `FactRecord` | 一条带来源引用的公开事实，不是人设。 |
| `Persona` | 虚拟居民。属性级 provenance，而不是整个人一个标签。 |
| `Edge` | 两人之间的一条关系，带类型、权重、`rule_id`。 |
| `Cohort` | 人群包：成员、角色、关系子图。 |
| `RunManifest` | 一次调研或评测运行的可复现记录。 |
| 双基线 | `no_external_data` 与 `no_social_rules`。 |
| 朴素对照 | `direct_llm` 与 `random`。命题要求至少一臂；演示默认 `direct_llm`。 |
| `QualityGate` | L5 验收门。Phase-1 的通过定义见第 4.3 节。 |
| `extension_point` | 愿景接缝，无 Phase-1 实现。 |
